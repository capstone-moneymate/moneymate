# worker/concepts/prereq_votes.py

- **한 줄 설명**: 개념 지도 ④. "A를 알아야 B를 이해할 수 있나?"를 개념 쌍마다 독립으로 4번 묻고 다수결로 선수 관계를 정한다 (#198). proposals.py의 "2회 일치"를 넓힌 방식이다.
- **입력**: ③이 만든 `ConceptNode` 목록, 임베딩 유사도 행렬(없어도 됨). 호출은 Haiku (`llm_client`로 월 한도·비용 기록, module=`concept_map`).
- **하는 일**: ① 후보 쌍: 모든 쌍을 묻지 않고, 같은 카드에 같이 나온 쌍을 먼저 넣고, 그다음 개념마다 임베딩이 가까운 이웃 3개를 유사도 높은 순으로 넣는다. 상한은 400쌍이다. ② 쌍마다 4번 독립 호출한다. 답은 first / second / none이고, 이유를 먼저 쓰게 한다. 호출마다 두 개념의 순서를 번갈아 바꾸고(원래 2번 + 바꾼 순서 2번), 답을 원래 방향으로 되돌려 센다. ③ 한 방향이 3표 이상이면 선수 관계로 남긴다. 표가 갈리거나 none이 과반이면 넣지 않는다.
- **출력**: `Prereq(pre, post, votes, total)` 목록과 개수 요약(쌍, 호출, 연결, 갈림, 관계 없음). 계획 6장의 `concept_prereq(pre_id, post_id, votes)`와 같은 모양이다.
- **주의할 점**: 선수 관계는 인과가 아니다 ("EPS를 이해하려면 순이익을 먼저 알아야 한다"는 배우는 순서). 프롬프트에도 그렇게 적었다. **4번인 이유**: LLM은 앞에 나온 쪽을 고르는 버릇(위치 편향)이 있다. 3번이면 원래 순서 2번 + 바꾼 순서 1번이라 버릇만으로 2:1이 나와 연결이 생긴다. 4번이면 정확히 2:2로 상쇄된다. 다수결은 답이 안정적이라는 뜻이지 맞다는 뜻이 아니다. 같은 프롬프트라 같은 착각을 반복할 수 있다. 순환 검사와 순환 끊기(표가 적은 연결부터 빼기)는 1-2 `prereq.dl`이 맡는다. 비용은 후보 쌍 × 4회이고, 400쌍이면 1,600회다.
- **테스트**: `cd worker && python -m pytest tests/test_prereq_votes.py -q` (실제 API 없이: 후보 쌍 순서·상한·임베딩 없음, 다수결 손계산 3표·4표, 순서를 바꿔도 같은 방향으로 셈, 위치 편향이 4표에서 상쇄되고 3표에서는 통과함, 개수 요약, 스키마·잘린 응답).
