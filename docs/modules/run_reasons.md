# worker/scripts/run_reasons.py

- **한 줄 설명**: 탭 2 카드 ②(이유)와 ③(지금은)을 13F 분기마다 겹침 결과의 모든 종목에 대해 만들어 `stock_reasons`에 저장한다. 13F 분기 갱신(check_13f_quarter.md 1~4단계) 뒤에 한 번 돌린다.
- **입력**: `--period`(13F 분기 말), `--ticker`(한 종목만), `--no-llm`(방향·근거 수만, 저장 안 함). DB의 그 분기 `overlap_results`(가장 최근 `calc_date`)와 `holdings_13f`(change_type·종목명), `raw_sources`(근거), `prices`. 실행: `cd worker && python -m scripts.run_reasons --period 2026-09-30 [--ticker NVDA] [--no-llm]`.
- **하는 일**: 종목마다 ① `reasons.stock_direction`으로 방향·change(P19, reasons.md "종목 단위 방향") ② 카드 ① 숫자 문장을 코드로 만든다. 큰손은 한 번씩 "드러켄밀러의 회사 09/30 기준 +24%"(새로 담음·모두 정리는 말로), ETF도 한 번씩 "TIME 09/30 대비 +15%"(P2 비율 × 100, 소수 첫째 자리) ③ `load_evidence`(기준일 이전 92일) → 경기 국면(#183: 분기 말이 속한 달, 양쪽 이유면 ETF 최신일이 속한 달로 `regime.regime_for_month`) → `reasons.generate`(Sonnet, 근거가 없으면 호출 안 함, `regime=`·`etf_regime=`). 침체 국면이면 출력 줄 끝에 "국면 recession/…" ④ 이유가 있으면 미국 종가를 기준일 10일 전부터 받고(`fill_prices`, 실패해도 계속) `stock_now.generate`(카드 ③, Haiku) ⑤ `reasons.save` → published / rejected. 종목마다 commit해서 중간에 멈춰도 앞 종목은 남는다.
- **출력**: 종목마다 한 줄(티커, 방향, change, 근거 수, 저장 status, 호출 수, 방향을 못 정한 까닭)과 합계(published·rejected·방향 못 정함).
- **주의할 점**: 큰손·ETF 이름은 web `labels.ts`와 손으로 맞춘 상수다(FILER_PERSON·ETF_SHORT). 비용은 종목마다 Sonnet 1~2회 + Haiku 1~2회라 종목 수만큼 든다. 먼저 `--no-llm`으로 종목 수·근거 수를 보고 돌린다. 13F 종목은 대부분 미국이라 근거(8-K)와 가격이 있어야 이유·카드 ③이 나온다(`EDGAR_IDENTITY` 필요, `collectors/prices.py us`). 근거가 없는 종목은 rejected로 저장된다(서버는 published만 읽음). 카드 ③은 날마다 바뀌어서 run_daily "탭2 지금은" 단계가 published 종목의 `now_view`만 다시 만든다(그 단계가 미국 가격도 기준일부터 채운다).
