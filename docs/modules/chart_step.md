# web/src/pages/tab1/steps/ChartStep.tsx

- **한 줄 설명**: 탭 1 차트 읽기 단계의 가격·거래량 차트. `lightweight-charts`로 그리며, 지금은 목 데이터를 쓴다.
- **입력**: 단계 id와 종목(`stepId`, `ticker`). 데이터는 `api/charts.ts`의 `useChart`가 준다: `points`(날짜, 종가, 거래량, 있으면 RSI)와 `highlight`(문제에서 말하는 날). 형식은 `types/chart.ts`.
- **하는 일**: 위 칸에 종가 선, 아래 칸에 거래량 막대를 그린다. `highlight` 날의 막대는 파란색이다. RSI 값이 있으면 맨 아래에 RSI 칸을 더하고, 축을 0~100으로 고정해 70·30 기준선이 항상 보이게 한다. 불러오는 중이거나 데이터가 없으면 안내 문구를 보여 준다.
- **출력**: 화면. 질문·보기·채점은 `QuizView`가 그대로 맡는다.
- **주의할 점**: 화면은 숫자를 계산하지 않고 받은 값만 그린다(CLAUDE.md "정답은 코드가"). 정답을 드러내는 날은 `highlight`에 넣지 않는다(예: "거래량이 가장 많았던 날" 문제). 손가락으로 차트를 밀어도 페이지가 스크롤되게 확대·이동을 껐다. 출처 로고가 거래량 막대를 가려 `attributionLogo`를 끄고, 라이선스가 요구하는 TradingView 링크는 차트 아래 설명에 넣었다. 목 데이터는 가상의 값이고 단계 id로 찾으며, `cardDetail.ts`의 목 정답과 맞춰 두었다. 표시 기간과 실제 API는 C와 정하기 전이라 화면용 `ChartStep` 타입(`types/card.ts`)은 바꾸지 않았다.
- **테스트**: web에는 단위 테스트 환경이 없어 브라우저로 확인한다. `cd web && pnpm dev` 후 `/news/mock-rate-hold/learn`(유형 2), `/news/mock-kospi-3up/learn`(유형 1)을 차트 단계를 지나 판단해보기까지 진행한다. 2026-11-07 Edge 390×844에서 두 흐름 모두 콘솔 오류 없음, 가로 스크롤 없음, 버튼이 아래 메뉴에 가리지 않음을 확인했다. RSI 칸과 데이터 없음 화면은 브라우저에서 응답을 바꿔 확인했다(목 데이터에는 RSI가 없다). 실제 휴대폰으로는 확인하지 않았다.
