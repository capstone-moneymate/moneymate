# worker/learner/schedule.py (FSRS 복습 일정)

- **한 줄 설명**: 개념마다 "기억이 얼마나 단단한가"(안정도)를 계산해 잊기 직전에 복습일을 잡는다 (계획 2-4). 일정 계산은 공식 구현 `py-fsrs`(open-spaced-repetition, Anki에 내장된 스케줄러와 같은 FSRS-6. Anki에서는 사용자가 켜는 옵션이다)를 그대로 쓰고, DB를 모르는 순수 계산이다.
- **입력**: 답 하나의 정답 여부, 확신(1 헷갈려요 / 2 확실해요 / 없음), 응답 시간, 답 변경 횟수, 그 개념의 지금 기억 상태 `Memory(stability, difficulty, last_review, due)`(처음이면 None), 시각.
- **하는 일**: ① `rate`: 사용자가 누르던 평가 버튼을 코드가 대신한다. 틀림 → Again, 맞힘 + 헷갈려요 → Hard, 맞힘 + 확실해요(또는 확신 없음) → Good, 맞힘 + 확실해요 + 빨랐고 답을 안 바꿈 → Easy ② `is_fast`: "빨랐다"는 고정된 초가 아니라, 내가 같은 형식 문제를 맞혔던 지난 응답 시간 중 빠른 쪽 1/4 안에 드는지로 본다 (기록이 8개보다 적으면 시간은 안 본다) ③ `review`: 평가를 FSRS에 넣어 새 안정도·난이도·다음 복습일을 받는다 ④ `retrievability`: 지금 기억하고 있을 확률.
- **출력**: `Rating`(Again/Hard/Good/Easy), 새 `Memory`, 기억 확률(0~1).
- **손계산** (처음 보는 개념, 기본 가중치): 처음 안정도는 평가별 가중치 그대로 Again 0.212일, Hard 1.2931일, Good 2.3065일, Easy 8.2956일. 안정도는 기억 확률이 90%로 떨어질 때까지 걸리는 날 수이고, 다음 복습은 그 날 수를 반올림(최소 1일)해서 Again·Hard 1일 뒤, Good 2일 뒤, Easy 8일 뒤. 처음 난이도는 `w4 - e^(w5 × (평가 - 1)) + 1`이라 Good이면 `6.4133 - e^(0.8334 × 2) + 1 = 2.118`. Good을 복습일마다 이어 가면 간격이 2 → 11 → 46일로 늘고, 틀리면 3일로 줄었다가 다시 8일로 는다.
- **숫자의 출처**: 가중치 21개와 목표 기억 확률 0.9는 `py-fsrs` 공개 기본값이다 (실제 복습 기록으로 학습된 값). **우리가 정한 값**은 세 가지다: 하루 상한 5개(계획의 예시), "빨랐다" 기준인 빠른 쪽 1/4과 최소 기록 8개. 뒤의 둘은 문헌 값이 아니다. 근거 자료는 아래 "근거" 줄에 있다.
- **근거 (2026-11-24 확인)**: ① 평가의 뜻은 Anki 공식 매뉴얼(Studying, answer buttons)의 정의를 옮겼다. Hard는 맞혔지만 의심이 있었거나 떠올리는 데 오래 걸린 경우, Easy는 맞혔고 힘이 들지 않은 경우, 버튼 4개가 어려우면 Again·Good만 써도 된다. SM-2 원문(Wozniak 1990)도 "완벽한 답 / 망설인 뒤 맞힘 / 매우 어렵게 맞힘"을 구분한다 ② 목표 기억 확률 90%는 Anki 매뉴얼(Deck Options)의 기본값 ③ 응답 시간을 복습 간격에 쓰는 것: Mettler, Massey & Kellman (2016, JEP: General 145(7), 897–917)에서 정답 + 응답 시간으로 간격을 정한 방식이 고정 간격보다 직후·지연 시험 모두 나았다. Sense, Behrens, Meijer & van Rijn (2016, Topics in Cognitive Science 8(1), 305–321)은 그 학습자·그 문항의 예상 응답 시간과 실제 시간을 비교한다 (요약 페이지로 확인, 원문 확인 필요) ④ 속도만으로 Easy를 주지 않는 이유: Benjamin, Bjork & Schwartz (1998)는 빨리 떠오른 것이 나중에도 잘 기억된다는 느낌이 틀릴 수 있음을 보였다 ⑤ 하루 상한: Anki 매뉴얼은 복습이 몰리는 날을 고르게 하고 쉬다 왔을 때 부담을 줄이려고 상한을 둔다고 설명한다. **"빠른 쪽 1/4", "기록 8개", "하루 5개"라는 숫자 자체의 근거는 찾지 못했다.** 민감도 분석이나 시간 예산으로 다시 정해야 한다.
- **원래 FSRS와 다른 점 (발표용)**: ① 평가를 사용자가 누르지 않고 정답·확신·시간·답 변경으로 자동으로 정한다 ② 복습 단위가 카드 한 장이 아니라 개념이고, 같은 개념을 매번 다른 문제로 묻는다 ③ 같은 날 다시 보는 단계(Anki의 1분·10분)를 뺐다. 하루 한 번 들어오는 앱이라 간격을 날 단위로만 둔다 ④ 복습 순서에서 "확실해요라고 했는데 틀린" 개념을 맨 앞에 둔다 (`state.due_reviews`).
- **주의할 점**: Easy는 다음 복습을 가장 멀리 미루는 평가라서 모든 신호가 같은 쪽일 때만 준다. 느리거나 답을 바꿨다고 Good을 Hard로 내리지는 않는다 (사용자가 직접 누른 확신이 시간보다 먼저다). 날짜를 흩뜨리는 기능(fuzzing)은 꺼서 같은 입력이면 같은 일정이 나온다. 기억 확률은 지난 시간을 날 단위로 센다 (패키지 동작). 응답 시간은 벽시계 시간이라 자리를 비우면 길게 나오지만, 길면 Easy가 안 될 뿐이라 일정이 잘못 늘어나지는 않는다. 가중치를 우리 데이터로 다시 학습하는 것(FSRS optimizer)은 기록이 쌓인 뒤의 일이다.
- **테스트**: `cd worker && python -m pytest tests/test_schedule.py -q` (15개: 자동 평가 4가지 규칙, 화면 글자 받기, 빠른 쪽 1/4, 처음 안정도·복습일·난이도 손계산, 안정도만큼 지나면 기억 확률 0.9, 맞히면 늘고 틀리면 줄어드는 간격, 쉬운 개념이 더 오래 기다림, 같은 입력 같은 일정, 시간대 없는 시각 거부).
