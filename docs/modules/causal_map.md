# web/src/pages/tab3/ 인과 지도 (CausalMapPage.tsx, CausalMapView.tsx, causalMapLayout.ts, MapNodes.tsx, mapColors.ts)

> 마이페이지 홈(시안 26)과 다시 보는 개념은 [review_list.md](review_list.md).

- **한 줄 설명**: 탭 3 "나의 인과 지도"(시안 27, `/mypage/map`). 배운 개념을 마인드맵 모양(가운데 뿌리, 테마는 좌우 가지)으로 React Flow(`@xyflow/react`)에 그린다. 테마를 누르면 접고 펴며, 개념을 누르면 그 개념의 연결이 전부 보인다.
- **입력**: `api/mypage.ts`의 `useCausalMap`이 주는 `{ nodes: [{ id, name, theme, correct, total, learned }], edges: [{ from, to, forceDir: 'up' | 'down' }] }` (`types/causalMap.ts`, 서버 `MypageDtos`와 같은 이름). `VITE_USE_MOCK`이 `false`면 `GET /api/mypage/map?userId=`, 아니면 `api/mocks/causalMap.ts`(테마 6개, 개념 48개 중 안 배운 개념 6개, 연결 57개. 사전 17·14 + 가짜). 주소의 `?focus=개념id`가 있으면 그 개념을 고른 채로 연다(홈의 다시 보는 개념에서 들어올 때).
- **하는 일**: `causalMapLayout.ts`(순수 함수)가 배운 개념(`learned: true`)만 놓는다. 테마는 오른쪽부터 더 낮은 쪽에 번갈아 달고, 테마 띠 안에서는 같은 테마 안 연결의 가장 긴 경로(깊이)로 열을 나눠 원인이 안쪽·결과가 바깥쪽에 온다(왼쪽 가지는 거울처럼 뒤집음). **처음에는 가지와 같은 테마 안 인과선만 그린다.** 다른 테마로 가는 연결과 아직 안 배운 개념과의 연결은 개념 노드에 `+N`으로만 표시한다. 개념을 누르면 그 개념의 나머지 연결을 그리고, 화면에 없는 이웃(아직 안 배운 개념은 점선, 접힌 테마의 개념은 실선)은 고른 개념 옆 빈 열에 임시 노드로 놓는다(결과 쪽은 바깥, 원인 쪽은 안쪽, 다른 노드와 겹치면 한 열씩 더 나감). 나머지는 흐리게 하고 아래 정보 패널에 연결과 정답률을 보여 준다.
- **출력**: 화면. 서버에 쓰지 않는다.
- **주의할 점**: 선이 엉키는 원인이 테마를 넘는 연결이라, 그런 선은 고른 개념 것만 그린다(2026-11-16 B 결정: 처음에는 같은 테마 안 선만, 누르면 그 개념 선 전부). 연결 색은 올리는 힘 빨강, 누르는 힘 파랑이고 ▲▼ 기호는 붙이지 않는다. "복습 필요" 표시와 "큰손 기록" 구분은 두지 않는다(B 결정). 접힌 테마로 드나드는 선은 합치지 않는다(전에는 테마 노드로 합쳤음). 첫 화면은 뿌리와 테마 노드만 읽히는 크기로 맞추고(개념은 손가락이나 −·전체 버튼으로 축소해서 본다, 2026-11-16 B 결정), 화면 맞춤은 전체·테마 접기/펴기·개념 고르기 때만 하고, 선택을 풀 때는 화면을 그대로 둔다. 노드 드래그는 껐다. 배운 개념이 없으면 안내 문구를 보여 준다. 테마 색은 테마 순서(`themesOf`)대로 매긴다. 정보 패널은 `정답률 N%`만 쓴다.
- **테스트**: web에는 단위 테스트 환경이 없어 브라우저로 확인한다. `cd web && pnpm dev` 후 `/mypage/map`. 2026-11-16 Chrome 390×844 모바일 에뮬레이션(Playwright, 목 데이터): 홈 "지도 열기" → 지도, 개념 선택 시 다른 테마 선과 안 배운 이웃(외환보유액, 점선) 표시·겹침 없음, 다시 보는 개념 → `?focus=energy_earnings`로 그 개념과 이웃에 맞춤. 콘솔 오류·경고 없음, 가로 스크롤 없음. 실제 서버(`VITE_USE_MOCK=false`)와 실제 휴대폰으로는 확인하지 않았다.
