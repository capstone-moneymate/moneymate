# worker/tutor/quiz.py

- **한 줄 설명**: 개념 단계 퀴즈 7종류를 만들고(Haiku), 모양을 검사하고, 채점하고, 찍어서 맞힐 확률을 코드로 계산한다 (#201).
- **입력**: 종류, 개념 이름, 개념 설명(desc, 정답의 근거), 헷갈리는 쌍이면 두 개념 이름, 짝 맞추기면 용어 3개. 호출은 `llm_client.create`(module=`tutor_quiz`), 종류마다 JSON 스키마를 쓴다.
- **하는 일**: 화면 A(보기 고르기)는 용어 뜻(3지선다), 헷갈리는 쌍(두 개념 이름), 틀린 설명(3개 중 틀린 것), O/X. 화면 B(칩을 칸에 넣기)는 칩 빈칸(칩 4개·빈칸 2개), 짝 맞추기(3쌍), 사례 분류(바구니 2개·사례 4개, 두 바구니 모두 사용). 코드 검사: 보기 수, 보기 중복, 정답 번호 범위, 헷갈리는 쌍 보기가 두 개념 이름 그대로인지, 빈칸과 정답 수, 금지 표현. 틀리면 한 번 더 만들고, 또 틀리면 `QuizError`.
- **출력**: `Quiz(kind, concept, content, key, explanation, guess_p)`. `content`는 화면용이라 정답이 없고, `key`는 서버만 본다. `grade(quiz, answer)`는 답이 `key`와 같은지 본다.
- **찍어서 맞힐 확률 (손계산)**: 용어 뜻·틀린 설명 1/보기 수(3지선다 33%), 헷갈리는 쌍·O/X 1/2, 칩 빈칸 1/(4×3) ≈ 8%, 짝 맞추기 1/3! ≈ 17%, 사례 분류 1/2⁴ ≈ 6%. 계획 1-3 표의 숫자와 같다. 튜터에게 넘기고, 나중에 BKT 추측 확률로 쓴다.
- **정답 위치 (#231)**: LLM 에게 칩 번호를 세게 하지 않는다. 2026-11-24 칩 빈칸 6번 중 5번 Haiku 가 칩 번호를 1부터 세서(코드는 0부터) 모양 검사는 통과하고 정답이 틀렸다(맞게 고른 학습자가 틀렸다고 나옴. 마지막 칩이면 4가 나와 출제 실패). 그래서 칩 빈칸 정답은 칩 글자 그대로 받고 (띄어쓰기는 무시) 코드가 번호로 바꾼다. 또 LLM 은 정답을 첫 보기에 두는 버릇이 있어서(용어 뜻·헷갈리는 쌍 4번 모두 0번) `generate`가 `shuffle`로 보기(용어 뜻·헷갈리는 쌍·틀린 설명)·칩·사례 순서를 섞고 정답 번호를 따라 옮긴다. 찍어서 맞힐 확률이 위 손계산대로 되려면 섞어야 한다. O/X는 늘 O, X. 짝 맞추기는 화면이 섞는다. 사람2의 `learner/review.py`도 보기를 섞는데, 한 번 더 섞여도 고르게 섞인 건 그대로라 괜찮다.
- **내용 검사 (#234)**: 정의를 묻는 문제는 코드가 맞는지 계산할 수 없어서, 칩 빈칸·용어 뜻·틀린 설명·사례 분류는 출제와 **따로 부르는** 검사(`check`, Haiku)를 거친다. 퀴즈를 "참이어야 하는 문장 / 거짓이어야 하는 문장"으로 펼치고(`claims`: 칩 빈칸은 정답을 채운 문장과 오답 칩을 한 칸씩 넣은 문장, 용어 뜻은 "개념의 뜻: 보기", 틀린 설명은 보기 그대로, 사례 분류는 "사례 → 바구니"), 어느 쪽이 정답인지는 숨기고 문장마다 참·거짓·애매를 묻는다(보여 주면 맞장구친다). 코드가 비교해서 하나라도 다르거나 애매하거나 매수·매도 권유가 있으면 버리고 새로 낸다. 그래서 다시 내는 횟수를 2 → 3으로 늘렸다. O/X·헷갈리는 쌍·짝 맞추기는 아직 검사하지 않는다. **칩 빈칸만 출제를 Sonnet으로** 한다(`GEN_MODEL`). 2026-11-24 측정(개념 5개 × 종류마다 2개, 사람이 읽고 판정): 검사 전 칩 빈칸 3/10, 틀린 설명 3/9가 틀린 퀴즈(용어 뜻 0/9, 사례 분류 0/10). 검사 뒤 틀린 설명 0/9. 칩 빈칸은 Haiku로는 검사를 붙여도 10개 중 4개만 나오고 그중 2개가 틀려서("[영업이익]은 매출에서 [매출원가]를 뺀 값") Sonnet으로 바꾸니 10개 중 9개가 나오고 9개 모두 맞았다. 비용: 검사 한 번 약 $0.0003, Sonnet 칩 빈칸 한 개 약 $0.003. 퀴즈를 만드는 시간은 검사만큼 늘어난다.
- **주의할 점**: 정의를 묻는 문제는 정답이 맞는지 코드가 계산할 수 없다. 그래서 개념 지도 설명을 근거로 주고, 코드는 모양만 본다. 설명이 비어 있으면 LLM 지식에 기댄다. 짝 맞추기는 뜻을 용어와 같은 순서로 받고 화면이 섞는다. 답은 용어 순서대로 원래 뜻 번호다.
