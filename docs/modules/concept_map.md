# worker/concepts/concept_map.py

- **한 줄 설명**: 퀴즈 앞 "개념" 단계 용어로 개념 노드와 선수 관계를 자동으로 만든다 (계획 1-1, #198). 탭 1 인과 사전과는 별개이고 그 사전은 고치지 않는다.
- **입력**: DB의 `steps`(kind=`concept`의 `content.terms` = `[{term, desc}]`)와 `card_sources` → `raw_sources.title`. 반려된 카드는 뺀다. 실행은 `cd worker && python -m concepts.concept_map`. `--extract`면 ②까지 (카드마다 Haiku 1회, `llm_client`로 월 한도·비용 기록, module=`concept_map`), `--limit N`은 앞 N장만, `--save`는 파일 저장.
- **하는 일 ①**: 용어를 카드 순서대로 읽고, 띄어쓰기·대소문자·괄호 안 글자만 다른 용어("기준 금리"/"기준금리", "eps"/"EPS", "지수 기여도(%p)"/"지수 기여도")를 하나로 합친다 (`term_key`). 괄호 규칙은 2026-11-24 실제 카드에서 같은 뜻으로 확인된 쌍이 모두 괄호만 다른 표기여서 넣었다 (#203, term_groups.md 기준값 항목). ②에서 "제목에 글자 그대로 있나"를 볼 때는 괄호 안 글자도 제목의 일부라 `squash`(괄호를 남김)를 쓴다. 용어마다 나온 카드 id를 모으고, 다른 카드에서 쓴 다른 설명은 `descs`에 남긴다. 뜻이 같은 다른 말("EPS"/"주당순이익")은 여기서 묶지 않는다 (③ 임베딩 담당).
- **하는 일 ②**: 1차 자료가 있는 카드마다 제목과 그 카드의 기존 용어를 주고 빠진 용어를 받는다 (JSON 스키마). 코드가 거른다: 빈 값, 20자 초과, 숫자만, **제목에 글자 그대로 없음**(띄어쓰기·대소문자 무시), 이미 있음, 금지 표현, 카드당 5개 초과. 다른 카드에 이미 있던 용어면 새로 만들지 않고 그 용어의 `card_ids`에 이 카드를 더한다. 새 용어는 `origin="source"`.
- **출력**: `Materials(terms, sources)`. 개수와 버린 용어·이유를 출력하고, `--save`면 `logs/concept_map/materials.json`에 저장 (Git에 올라가지 않음).
- **주의할 점**: 기사 본문은 저장하지 않으므로 1차 자료는 제목만 쓴다. ②는 proposals.py처럼 2회 일치를 보지 않는다. 대신 "제목에 있는 말인가"를 코드가 확인해서, LLM이 지어낸 용어는 남지 않는다. 다만 제목에 있는 말이라도 초보자가 배울 용어인지는 LLM 판단이다. `desc`는 LLM이 쓴 뜻풀이라 정답으로 쓰지 않는다. 처음 나온 표기·설명을 대표로 쓰고 순서를 지켜서, ①은 같은 DB면 돌릴 때마다 결과가 같다 (②는 LLM이라 다를 수 있다). 다음 단계: ③ 임베딩 묶기 (모델 미정), ④ 다수결 선수 관계, ⑤ 저장 (009 마이그레이션 전에는 파일).
- **테스트**: `cd worker && python -m pytest tests/test_concept_map.py -q` (DB·실제 API 없이: ① 띄어쓰기·대소문자 합치기, 순서 유지, 빈 용어·terms 없음·같은 카드 중복, 저장 파일 모양 / ② 거르기 7가지, 새 용어 추가와 기존 용어 연결, known에 이 카드 용어만 넘김, 자료 없는 카드 건너뜀, 잘린 응답).
