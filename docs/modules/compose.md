# worker/generate/compose.py (+ prompts/compose.md)

- **한 줄 설명**: 출제 에이전트. Claude Sonnet이 1차 자료 1건과 유형·시작 개념을 받아 tools.py 도구로 숫자·경로를 얻고 카드뉴스·단계를 만든다. 코드가 검증하고 통과하면 `pending`으로 저장한다 (기술확정안 6·7·8단계).
- **입력**: `raw_sources` 한 행, classify 결과(`card_type`, `start_concept`), 카드 날짜. 개념 사전은 시스템 프롬프트 끝에 붙인다. 유형 3이면 그 종목을 담은 ETF의 최신 수량 변화(`holdings_etf`)를 함께 준다. 변화율은 소수(0.053097)로 저장돼 있어서 코드가 "9/30 대비 +5.3%"처럼 문구로 바꿔 넘기고, NULL은 "9/30 이후 신규 편입"(기준일은 `trend_base_date`)으로 쓴다 (LLM이 ×100 하지 않게).
- **하는 일**: ① tool use 루프를 직접 돌린다 (`messages.create` + 도구 7개 + `submit_card`, effort medium, 대화 캐시). API 호출은 카드 1건에 `MAX_CALLS`(15)번까지. ② 에이전트가 `submit_card`로 카드를 내면 코드가 검사한다: 카드 모양(스키마), 유형별 단계 순서, 개념 id(judgement의 chain·counter 포함), 인과 순서(B의 validators), 차트 숫자(다시 계산하고, 그 값이 정답 보기 문장에 있고 다른 보기에는 없는지. '3'/'3.0'/'3배', '10월 30일'/'10/30'처럼 표기가 달라도 숫자로 비교하고 보기에 쓴 자릿수만큼 오차 허용), 보기·정답 번호, 금지 표현, key_facts. ③ 실패하면 이유를 `submit_card`의 오류 결과로 돌려줘 고치게 한다 (최대 3번). ④ 통과하면 `cards`(pending)·`card_sources`(is_main)·`steps`에 저장하고, 이 카드를 만든 호출의 `llm_cost_log.card_id`를 채운다.
- **출력**: `ComposeResult(card_id, card, errors, calls, repairs, cost_usd, request_ids)`. 끝내 통과하지 못하면 `card_id=None`, `errors`에 마지막 이유.
- **저장 모양**: `steps.content`는 화면에 내려보내는 부분(snake_case, `concept_ids` 포함), `steps.answer`는 서버만 보는 정답. quiz·chart `{correct, explanation}`(chart는 `check`도), causal_order `{correct: 경로, explanation, change, direction, evidence_quote}`, judgement `{chain, counter}`(A의 채점용). 인과 순서 보기는 자료 키로 고정 시드를 써서 섞고, 정답 순서와 같아지지 않게 한다.
