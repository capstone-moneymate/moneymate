- **경기 국면 (2026-11-19 B, #174)**: `compose(..., regime=)`를 주지 않으면 카드 날짜의 달로 `concepts.regime.regime_for_month`가 국면을 정한다(삼의 법칙 지표 앞 달 값 ≥ 0.5면 recession, regime.md). 그 국면을 `ToolContext.regime`에 넣어 경로 찾기·인과 순서 검증과 마지막 `verify`가 그 국면 연결로 계산하고, 침체면 사용자 메시지 끝에 "지금은 경기 침체 국면이에요 …" 한 줄을 붙인다. 저장할 때 `model_info.regime`에 `{name, sahm, observed, source}`를 남긴다. 평상시면 프롬프트·결과가 예전과 같다.

- **저장 모양**: `steps.content`는 화면에 내려보내는 부분(snake_case, `concept_ids` 포함), `steps.answer`는 서버만 보는 정답. quiz·chart `{correct, explanation}`(chart는 `check`도). chart의 `content`에는 화면이 그릴 기간 `start_date`·`end_date`('YYYY-MM-DD', 끝 = 확인한 날. 기간 문제 top_volume_date·return_pct는 시작 = 문제 기간 시작이라 화면에 문제 기간만 보이고, 하루 문제 volume_ratio·rsi는 시작 = 90일 앞)와 차트에 그릴 값 `chart`를 넣는다(B 요청). `chart`는 B의 `ChartData` 모양이다: `points`(표시 기간의 `date`·`close`·`volume`, rsi 문제만 `rsi`. RSI는 정답 확인 도구 `calc_rsi`와 같은 마지막 252거래일로 `indicators.rsi_series`를 돌려 잘라서 그날 값이 정답과 같다), `highlight`(하루 문제 volume_ratio·rsi만 그날 `{date, label: '문제의 날'}`. 기간 문제는 정답을 드러낼 수 있어 넣지 않는다). 출제 때 값을 고정해 가격을 다시 수집해도 이미 낸 문제의 차트는 바뀌지 않는다, causal_order `{correct: 경로, explanation, change, direction, evidence_quote}`, judgement `{chain, counter}`(A의 채점용). 탭 3 기록(user_concepts)은 답안 API 가 `content.concept_ids`, 판단 채점이 `answer.chain`에서 개념을 읽으므로, judgement 의 `content.concept_ids`에는 chain 개념을 빠짐없이 더해 저장한다(순서 유지, 중복 없음). 모든 단계의 concept_ids·chain·counter 는 사전 id 인지 검증에서 확인한다. 인과 순서 보기는 자료 키로 고정 시드를 써서 섞고, 정답 순서와 같아지지 않게 한다.
