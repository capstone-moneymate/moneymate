# worker/collectors/dart_numbers.py

- **한 줄 설명**: DART 공시 원문(document.xml) 표에서 핵심 숫자만 코드로 뽑아 `raw_sources.numbers`에 넣는다. 공시 이름만으로는 실적이 좋았는지, 계약이 회사에 얼마나 큰지 알 수 없어서 classify·proposals·compose가 방향을 몰랐다(2026-11-16 실데이터 확인).
- **입력**: 공시 접수번호(rcept_no), 종류(`category`), 제목. `sources.fetch_dart`가 거르기를 통과한 공시마다 `fill_dart_numbers`로 부른다.
- **하는 일**: ① document.xml zip을 받아 본문 XML을 읽는다(meta에 euc-kr이라고 적혀 있어도 실제로는 UTF-8인 경우가 있어 UTF-8 먼저, 안 되면 cp949) ② `<TR>`의 칸을 줄 단위로 읽는다 ③ 서식별로 값을 고른다:
  - 영업(잠정)실적: 실적기간, 단위, 매출액·영업이익·당기순이익의 당기·전년동기 값, 전년동기대비·전기대비 증감률(%)과 방향
  - 매출액또는손익구조30%변동: 같은 세 항목의 당해·직전 값, 증감비율, 방향, 당해·직전 기간, 변동 주요원인
  - 단일판매ㆍ공급계약: 체결계약명, 계약금액(원), 최근매출액(원), 매출액대비(%), 계약상대, 공급지역, 계약 시작·종료일
  - 자기주식취득결정: 취득예정주식(주), 취득예정금액(원), 취득 시작·종료일, 취득목적, 취득방법
  - 주식소각결정: 소각주식(주), 발행주식총수(주), 발행주식대비(%)(코드 계산), 소각예정금액(원), 소각예정일. 종류주식만 소각하면 '종류주식 ' 이 붙은 키
  - 신규시설투자: 투자대상, 투자금액(원), 자기자본(원), 자기자본대비(%), 투자목적, 투자 시작·종료일
  - 자회사 주요경영사항 공시면 `자회사`에 자회사 이름
- **출력**: 한국어 키의 평평한 dict (compose 프롬프트에 `키: 값`으로 그대로 보인다). 금액은 공시 단위 그대로이고 실적은 `단위`(억원·백만원·천원)를 함께 넣는다. 서식이 안 맞거나 값이 모두 '-'면 빈 dict.
- **주의할 점**: 숫자는 공시 표의 값을 옮기기만 하고, 코드가 계산하는 것은 발행주식대비(%)와 방향(증감률 부호, 공시의 흑자적자전환 칸)뿐이다. 본문은 저장하지 않는다(CLAUDE.md 9). 글 칸(계약상대·목적·원인)은 80자로 자른다. 원문을 못 받거나 서식이 달라도 수집은 멈추지 않고 경고만 한다. 월별 실적(현대차·기아 판매, 카지노, 이마트 등)은 값이 '-'이거나 매출액만 있다. 공시 1건마다 DART API를 1번 더 부른다(하루 50건 안팎, 한도 2만). 이미 저장된 자료는 `sources.py dart <날짜> --save`를 다시 돌리면 numbers가 합쳐져 채워진다(합치기라 예전 키는 남는다).
- **테스트**: `cd worker && python -m pytest tests/test_dart_numbers.py -q` (실제 서식을 따른 가짜 표로 손계산: 실적 당해 줄만 읽기·△ 음수·적자전환·적자지속, 값이 모두 '-'면 빈 dict, 손익구조 변동의 기간·원인 자르기, 공급계약·자회사, 자사주 취득 기간이 보유예상기간과 섞이지 않음, 소각 비율 2,000,000 ÷ 80,000,000 = 2.5%, 종류주식만 소각, 투자금액 유보, 숫자·날짜·방향 변환, UTF-8/cp949, zip 안 본문 고르기, 오류 응답). `tests/test_sources.py`: 원문 하나가 실패해도 나머지는 채움. 2026-11-16 실제 공시 11/2~11/13 506건으로 돌려 498건이 채워짐(빈 8건은 값이 '-'인 월별 실적).
