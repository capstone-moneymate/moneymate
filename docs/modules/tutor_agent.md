# worker/tutor/agent.py (+ mastery.py, demo.py)

- **한 줄 설명**: 퀴즈 앞 "개념" 단계를 사용자의 지식 상태에 맞춰 가르치는 튜터 에이전트 (계획 1-3, #201). 순서를 코드가 정하지 않고, 매번 도구 결과를 보고 모델이 다음 행동을 고른다.
- **입력**: `ConceptMap`(개념 이름·설명·선수 관계·헷갈리기 쉬운 이웃. `from_build`로 #198 `concept_map.json`에서 만들고, 만들 때 #199 `break_cycles`로 순환을 끊는다), 목표 개념, 사용자 id, 지식 상태(`get_mastery`). 모델은 Opus 5.5, effort low (`llm_client.create`, module=`tutor`).
- **하는 일**: 도구 4개. `ready_concepts`는 목표 개념 전부의 상태(앎 / 준비됨 / 선수 개념 먼저 + 모르는 선수 개념)와 준비된 개념(알 확률, 헷갈리기 쉬운 이웃)을 코드가 계산한다. `ask_quiz(concept, kind)`는 퀴즈를 만들고(`tutor/quiz.py`) 세션을 `waiting`으로 멈춘다. `answer()`로 답이 오면 채점 → 지식 상태 갱신 → 결과(정답, 확신, 찍어서 맞힐 확률, 지금 알 확률)를 넘기고 다시 돈다. `explain(concept, style, text)`은 에이전트가 쓴 설명을 화면 이벤트로 보낸다(금지 표현은 되돌린다). `go_main`은 끝낸다. 모든 도구에 `reason`을 먼저 쓰게 해서 `log`에 "무엇을 왜"가 남는다.
- **출력**: `Session`. `status`(running / waiting / done / error), `finished_by`(go_main / quiz_limit / call_limit / no_tool / stop:이유), `log`(단계마다 도구·입력·이유·채점 결과), `events`(화면용: quiz / graded / explain / done. 정답은 넣지 않는다), `messages`(대화 전체. 이어 가려면 그대로 다시 보낸다).
- **모델을 고른 근거**: 2026-11-23 `scripts/measure_tutor_latency.py`로 튜터 한 단계와 같은 요청을 비교했다 (상황 6개 × 4번). 규칙대로 고른 비율 Opus 5.5 low 20/24, Sonnet 5.5 low 15/24. 평균 2.8초 대 5.2초 (Sonnet 최대 32.7초). 1회 $0.009 대 $0.005.
- **비용 (프롬프트 캐싱)**: 튜터는 매번 대화 전체를 다시 보내서, 요청에 `cache_control`(자동 캐싱)을 켰다. 앞에서 보낸 부분은 입력 단가의 0.1배로 읽고, 모델이 받는 내용은 같다. 2026-11-23 시연(학습자 2명)에서 켜기 전에는 호출 19번 $0.31(1번 평균 $0.016), 켠 뒤에는 20번 $0.13(1번 평균 $0.0064)이었다. 입력 토큰의 89%(62,454 중 55,856)를 캐시에서 읽었다. 캐시가 깨지지 않게 `SYSTEM`과 `tools()`에는 시각 같은 바뀌는 값을 넣지 않는다.
- **주의할 점**: `mastery.py`의 `FakeMastery`는 **가짜**다. 사람2의 BKT(2-3)가 나오면 `get_mastery`·`update` 모양만 맞춰 바꾼다. 갱신 숫자(0.97 / 0.75 / 0.30)에는 근거가 없어서 평가·발표에 쓰지 않는다. 한 번에 도구 하나만 부르게 했다(`disable_parallel_tool_use`). Opus 5.5는 도구 강제(`tool_choice` any/tool)가 안 돼서, 글만 쓰고 도구를 안 부르면 한 번만 다시 부탁하고 그래도 안 부르면 끝낸다. 상한은 퀴즈 6개, 모델 호출 16번이다. 거절(`refusal`)이 오면 `error`로 끝낸다. 서버 대체 모델(fallbacks)은 `llm_client.create`가 베타 API를 쓰지 않아서 아직 켜지 않았다. 헷갈리기 쉬운 이웃(`confusable`)은 지금은 손으로 넣는다. 개념 지도 임베딩으로 자동으로 채우는 건 후속 작업이다. 세션은 아직 메모리에만 있다. 화면과 잇는 API(judge_api처럼 FastAPI)와 저장은 다음 단계다.
- **완료 기준 확인**: `python -m tutor.demo` (실제 API, 약 $0.1~0.3). 지식 상태가 다른 가상 학습자 2명(A: 기초는 앎·자사주 소각을 잘못 앎, B: 처음 배움)을 같은 카드로 돌려 고른 순서를 `logs/tutor_demo.json`에 남긴다. 가상 학습자는 간단한 규칙이고, LLM 학습자는 1-5에서 만든다.
- **테스트**: `cd worker && python -m pytest tests/test_tutor_agent.py -q` (가짜 모델 응답: 개념 지도 변환·순환 끊기·선수 개념 모으기, ready 손계산, 퀴즈에서 멈추고 답으로 이어가기·tool_result 연결·모델 설정, 퀴즈 실패를 에이전트에게 되돌림, 금지 표현 설명 거부, 퀴즈·호출 상한, 도구 없는 답 한 번 재요청, 거절, 이웃 없는 헷갈리는 쌍).
