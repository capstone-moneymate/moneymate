# worker/learner/bkt.py

- **한 줄 설명**: 답 하나가 들어올 때 개념의 "알 확률"을 고치는 BKT 계산 (계획 2-3). Corbett & Anderson (1995) 지식 추적의 식 그대로이고, DB를 모르는 순수 계산이다.
- **입력**: 지금 알 확률 `p`, 정답 여부, 추측 확률 `guess`(문제 형식에서 코드가 계산한 값. 4지선다 0.25, O/X 0.5, `tutor/quiz.py`의 `guess_p`), `Params(p_init 0.3, p_learn 0.1, p_slip 0.1)`.
- **하는 일**: ① 베이즈 갱신 `posterior`. 맞힘은 `p(1-실수) / (p(1-실수) + (1-p)추측)`, 틀림은 `p·실수 / (p·실수 + (1-p)(1-추측))` ② 배움 반영 `p' + (1-p')·배움`. `update`가 ①②를 이어서 한다. `corrects_to_know`는 처음 보는 개념을 몇 번 연달아 맞혀야 0.95(사람1 `prereq_check.KNOW_P`)를 넘는지 센다.
- **출력**: 새 알 확률 (0~1).
- **손계산**: 처음 0.3, 추측 0.25, 실수 0.1, 배움 0.1 → 맞힘 `0.27 / 0.445 = 0.607 → 0.646`, 틀림 `0.03 / 0.555 = 0.054 → 0.149`. 연달아 맞히면 0.30 → 0.65 → 0.88 → 0.97.
- **파라미터 근거**: 식은 논문, 추측은 문제 형식에서 계산한다. 실수·처음·배움 값은 우리 데이터로 학습한 값이 **아니다** (계획: 실수 0.1 이하, 나머지는 민감도 분석). 민감도 (처음 0.1·0.3·0.5 × 실수 0.05·0.1 × 배움 0.05·0.1·0.2, 18가지): "안다"까지 연달아 맞혀야 하는 횟수가 칩 빈칸(추측 0.08) 2~3번, 4지선다 2~4번, 3지선다 3~5번, O/X 4~8번. 기본값에서는 2 / 3 / 4 / 6번. 찍기 쉬운 문제일수록 더 많이 맞혀야 한다는 순서는 어느 값에서도 같다. 데이터가 쌓이면 pyBKT로 학습해 바꾼다.
- **주의할 점**: 추측은 0.01~0.5로 맞춰 쓴다. 0이면 한 번 맞힌 순간 알 확률이 1이 되고 그 뒤로는 틀려도 내려오지 않기 때문이다 (0.01은 계산용 하한이지 문헌 값이 아니다). 확신(헷갈려요/확실해요)은 BKT에 넣지 않는다. 알 확률은 정답과 추측 확률로만 고치고, 확신은 확신 보정(2-5)과 FSRS(2-4)가 쓴다. 선수 개념으로 증거를 퍼뜨리는 것은 아직 없다.
