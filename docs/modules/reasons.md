# worker/generate/reasons.py

- **한 줄 설명**: 탭 2 종목 상세 카드 ② "이유 (AI 추정)"를 만든다. 큰손·액티브 ETF가 왜 늘리거나 줄였을지 1~3개 이유를 쓰고, 이유마다 인과 뼈대와 근거 자료(날짜 포함)를 붙인다.
- **입력**: 종목(`ticker`, `name`), A의 `overlap_results.direction`(`same`·`diff`·`none`)과 큰손 쪽 변화(`up`·`down`), 공시 기준일(13F 분기 말), 카드 ① 숫자 문장(코드가 만든 것), 근거 후보. 근거 후보는 `load_evidence`가 `raw_sources`에서 그 종목 자료와 거시 발표 중 기준일 앞 92일 안(기준일 포함)에 나온 것을 최근 순으로 20개까지 번호를 붙여 고른다. 실행은 `cd worker && python -m generate.reasons NVDA 2026-09-30 same up "드러켄밀러 +24%"`.
- **하는 일**: ① 제목은 방향으로 코드가 정한다(같은 방향 늘림 "왜 다 늘렸을까요?", 줄임 "왜 다 줄였을까요?", 다름 "왜 방향이 다를까요?", 한쪽만 "왜 늘렸을까요?"). ② Sonnet 1회 호출(effort medium, `llm_client`로 비용 기록, module=`reasons`). 개념 id와 근거 번호를 JSON 스키마 enum으로 묶어 사전·입력 밖의 값은 나올 수 없다. ③ 코드 검사: 이유 1~3개, 근거 번호 1개 이상·입력에 있음·날짜가 기준일 이전, 시작≠끝이고 사전에 경로가 있음, 금지 표현(B의 `find_banned`). ④ 걸리면 이유를 돌려주고 1번 더 쓰게 한다.
- **출력**: `ReasonsResult(headline, reasons, errors, calls)`. 이유마다 `title`, `body`, `start_concept`, `end_concept`, `path`(B의 graph.py로 찾은 가장 짧은 사전 경로), `evidence`(번호·`raw_sources.id`·날짜·제목·발표 기관·URL). 끝내 통과하지 못하면 `reasons`가 비고 `errors`에 마지막 이유가 남는다. 근거 후보가 없으면 API를 부르지 않는다.
- **주의할 점**: 이유는 추정이다. 근거 번호를 고른 것이 그 자료가 이유를 증명한다는 뜻은 아니다. 숫자는 카드 ①과 자료 제목에 있는 것만 쓰게 했지만 문장 속 숫자를 코드가 다시 확인하지는 않는다(6주차 검토). 기사 본문은 넘기지 않고 제목만 쓴다(CLAUDE.md 9). 근거 날짜 검사는 지금 이 파일에 있고, B가 validators에 근거 날짜 검증기를 만들면 그것으로 바꾼다. 저장할 테이블이 아직 없어 결과는 출력만 한다(A에게 마이그레이션 요청 필요). 금리 뉴스와 AI 테마는 #67 이후 사전에서 이어지지 않아 그런 이유는 경로 검사에서 걸린다.
- **테스트**: `cd worker && python -m pytest tests/test_reasons.py -q` (가짜 응답: 방향별 제목 4가지, 정상 이유와 코드가 찾은 경로, 스키마 enum, 프롬프트 JSON 묶기, 불량 7가지, 기준일 뒤 근거, 금지 표현, 수정 1회 후 통과, 수정 상한, 근거 없으면 호출 안 함, 잘린 응답). **실제 API·DB로는 아직 확인하지 못했다**(raw_sources에 NVDA 자료와 3분기 13F 겹침 결과가 있어야 함).
