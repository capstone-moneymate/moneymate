# worker/concepts/prereq_check.py + prereq.dl

- **한 줄 설명**: 개념 지도 선수 관계의 순환을 Datalog 규칙으로 찾아 끊고, 사용자가 지금 배울 준비가 된 개념(`ready`)을 고른다 (계획 1-2, #199).
- **입력**: 선수 관계 `(앞, 뒤, 표)` 목록 (#198 ④ 다수결 결과, `concept_map.json`의 `prereqs`), 개념 목록, 사용자 id, 알 확률 `{개념: p}` (사람2 BKT의 `get_mastery`). 규칙은 `concepts/prereq.dl`, 엔진은 기존 `concepts/datalog.py`를 그대로 쓴다.
- **하는 일**: 규칙 파일이 판단 기준을 모두 정하고, 코드는 사실을 넣고 결론을 읽기만 한다. ① `reach`: 선수 관계를 따라 닿는 개념(고정점까지). ② `cyclic`: 자기 자신에게 돌아옴. ③ `cycle_edge(X, Y)`: X → Y가 있고 Y에서 X로 돌아올 수 있으면 순환 위의 연결이다. 코드는 그중 **표가 가장 적은 연결 하나**를 빼고 다시 계산하며, 순환이 없어질 때까지 반복한다. 표가 같으면 (앞, 뒤) 이름 순으로 먼저인 것을 빼서 결과가 매번 같다. ④ `missing(U, C)`: C의 선수 개념 중 U가 모르는 것이 있음 (부정 `!knows`). ⑤ `ready(U, C)`: U가 C를 아직 모르고 `missing`도 없음. 선수 개념이 없는 개념은 바로 준비된다.
- **출력**: `break_cycles` → `Checked(kept, removed)` (남긴 연결, 뺀 연결을 뺀 순서대로). `ready_concepts` → 준비된 개념 목록 (입력 순서 유지). 튜터 에이전트(1-3)의 `ready_concepts(user)` 도구가 이 함수를 쓴다.
- **주의할 점**: "안다"의 기준은 알 확률 0.95 이상이다 (`KNOW_P`, 경계 포함). Corbett & Anderson (1995) 지식 추적에서 숙달로 보는 값이고, 원문은 발표 전에 확인한다. 표가 적은 연결부터 빼는 이유는 다수결에서 덜 확실했던 연결이기 때문이다. 뺀 연결이 틀렸다는 뜻은 아니다. 선수 관계는 인과가 아니다(배우는 순서). `ready_concepts`에는 순환을 끊은 뒤의 연결을 넣어야 한다. 순환이 남아 있으면 순환 안의 개념은 서로를 기다리느라 영영 준비되지 않는다.
- **테스트**: `cd worker && python -m pytest tests/test_prereq_check.py -q` (손으로 만든 작은 그래프: 순환 없음, 순환 1개에서 표 동점이면 이름 순, 순환 2개를 하나씩, 자기 자신 순환, ready 손계산 4가지, 0.95 경계, 지식 상태가 다른 두 사용자가 다른 개념을 받음).
