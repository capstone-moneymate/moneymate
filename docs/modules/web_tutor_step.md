# web/src/pages/tab1/steps/TutorStep.tsx (+ TutorChoiceQuiz, TutorChipQuiz, TutorFeedback, api/tutor.ts)

- **한 줄 설명**: 탭1 개념 단계를 튜터 에이전트가 고른 설명·퀴즈로 진행하는 화면 (추가구현_계획 1-3, 화면 A·B).
- **입력**: 카드 id, 그 카드의 기존 개념 단계(ConceptStep, 튜터를 못 쓸 때 대신 보여 줌). API는 `POST /api/tutor/start`, `POST /api/tutor/{sessionId}/answer` (docs/modules/tutor_server_api.md). `VITE_USE_MOCK` 이 false 가 아니면 `api/mocks/tutor.ts` 가 7종류를 한 번씩 낸다.
- **하는 일**: 서버 이벤트를 하나씩 넘겨 보여 준다. explain → 설명 칸, quiz → 종류에 따라 화면 A(TutorChoiceQuiz: 용어 뜻·헷갈리는 쌍·틀린 설명·O/X, 보기 고르기) 또는 화면 B(TutorChipQuiz: 칩 빈칸·짝 맞추기·사례 분류, 칸을 고르고 칩을 눌러 넣기). 답은 [헷갈려요]/[확실해요]로 내고 응답 시간·답 바꾼 횟수를 같이 보낸다. 바로 뒤 graded 이벤트로 정답·해설을 그 퀴즈 화면에 표시하고, done 이면 목표 개념을 보여 주고 다음 단계로.
- **출력**: 없음 (답·확신·시간은 서버가 BKT·concept_answers 에 기록). 결과 화면 점수에는 넣지 않는다.
- **주의할 점**: 시작은 다시 부르면 세션과 모델 비용이 또 들어서 저절로 재시도하지 않는다(useQuery retry 끔, 화면을 떠나면 버림). 시작 실패(503·404·시간 초과)나 `no_targets` 면 기존 ConceptView. 답 중에 세션이 사라지면(404·409·503) "이어 가지 못했어요"와 다음 단계 버튼, 그 밖 오류는 "다시 눌러 주세요". 사례 분류는 바구니가 "이 개념에 해당"처럼 개념 이름 없이 올 수 있어 제목에 개념 이름을 넣는다("'자사주 소각' 사례를 알맞은 쪽에 넣어 주세요", #258). 짝 맞추기는 서버가 뜻을 용어 순서대로 줘서(정답이 늘 0,1,2) 화면이 섞어 보여 주고 원래 번호로 보낸다. 풀었던 내용 보기(?review)에서는 튜터를 열지 않는다.
- **테스트**: web 에 테스트 러너가 없어 `npx tsc -b`, `npx eslint src` 와 목 데이터로 브라우저에서 7종류를 끝까지 풀어 확인 (2026-11-25). 같은 날 실제 서버(채점 서버 + Spring + 모델)로 카드 17을 풀어 용어 뜻·헷갈리는 쌍·칩 빈칸·사례 분류 6문제 → 끝 → 간단 퀴즈까지 확인했고, concept_answers 에 확신·응답 시간·답 바꾼 횟수가 기록됐다. 짝 맞추기·틀린 설명·O/X 는 튜터가 고르지 않아, 출제기(make_quiz)로 실제 모델이 만든 퀴즈를 목 자리에 잠깐 넣어 풀어 확인했다(긴 보기·뜻 줄바꿈, 칸별 정답, O/X 오답 색). 설명(explain) 화면은 목 데이터로만 확인했다. 튜터 시작이 실패하면 기존 개념 설명으로 넘어가는 것도 확인했다(로컬 DB에 008 마이그레이션이 빠져 500이 났을 때).
