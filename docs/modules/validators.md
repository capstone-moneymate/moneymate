# worker/validate/validators.py

- **한 줄 설명**: LLM이 만든 인과 순서 문제를 개념 사전 계산 결과(`concepts/graph.py`)와 원문에 대조해, 통과 여부와 실패 이유를 돌려주는 검증기 최소 버전.
- **입력**: 퀴즈 dict(`start_concept`, `change`, `end_concept`, `answer_order`, `direction`, `evidence_quote`)와 원문 텍스트. 형식은 임시이고 C의 출제 결과 형식과 맞춘다. `g`를 주지 않으면 `db/seeds` 개념 사전을 쓴다.
- **하는 일**: ① 필드가 다 있고 `change`·`direction`이 up / down인지 ② 개념 id가 사전에 있는지 ③ 시작 → 결과 경로가 있는지 ④ 방향이 다른 경로가 함께 있으면 순서 문제로 부적합 ⑤ 정답 순서가 사전 경로 중 하나와 같은지 ⑥ 방향이 사전으로 계산한 방향과 같은지 ⑦ 인용한 근거가 원문에 그대로 있는지(띄어쓰기·줄바꿈 차이는 무시)를 검사한다.
- **출력**: `Report(errors, warnings)`. `errors`가 비어 있으면 `passed`. `errors`는 그대로 출제 단계에 돌려줘 다시 쓰게 하는 문장이다. `warnings`는 통과는 시키지만 사람이 확인할 것이다.
- **주의할 점**: 경로가 여러 개일 때는 그중 하나와 같으면 통과시키고 "원문 설명과 같은 경로인지 확인 필요" 경고를 붙인다(엄격하게 원문에 중간 개념이 나오는 경로만 통과시키면, 중간 과정을 적지 않는 공시가 많아 맞는 문제도 버릴 수 있어서). 같은 결론으로 가는 지름길 연결(예: `rate_hike → growth_valuation` 직접, 보류 상태)은 사전 정리 때 빼서 경로를 줄인다. 근거 날짜(탭 2)는 C의 reasons.py 입력 형식이 정해지면 만든다. 형식 검사는 C의 compose가 JSON 스키마로 하고(schemas.py는 만들지 않음, C와 합의), 숫자 재계산은 C의 tools.py가 한다.
- **테스트**: `cd worker && python -m pytest tests/test_validators.py -q` (손계산: 파월 예시는 인하 기대 down × (-1)×(-1)×(+1) = 하락 압력이 정답, 방향·순서·인용을 하나씩 틀린 불량 샘플, 모호한 쌍은 실패, 경로 2개는 통과 + 경고, 실제 사전의 인하 → 국채 금리 → 성장주).

- **주의할 점**: 시작 목록은 C의 compose `FORBIDDEN` 정규식을 옮겼고, 정상 문장을 잡던 세 패턴은 고쳤다(#60: "회사라.", "목표가 물가 안정", "반드시 오늘"). 그래서 compose의 `FORBIDDEN`과 결과가 다르며, compose가 `find_banned`로 바꾸기 전까지 compose에는 이 수정이 적용되지 않는다. 조사 없이 쓴 "삼성전자 사라!"는 사람 이름("사라 프라이어")을 걸지 않으려고 잡지 않는다. "매수세", "순매도", "목표 달성", "수익률"처럼 일반 표현은 걸지 않는다. 걸린 표현이 생기면 목록에 추가한다(분담표 6주차 금지 표현 정리).

## 중복 `find_duplicates(new_texts, past_texts, threshold=90) -> list[str]`
- **하는 일**: 새 문제 문장마다 예전 문제 중 가장 비슷한 것과 RapidFuzz `ratio`(문장 전체 글자 비교, 대소문자·문장부호 무시)로 비교해, 90점 이상이면 "다른 질문으로 바꿔 주세요" 오류 문장을 돌려준다. DB를 읽지 않는다. 예전 문제는 C가 `steps`에서 최근 N일치 quiz·chart 문제를 읽어 넘긴다. question만 넘기지 않고 question + 보기 문장을 이어서 넘기며, 새 문제도 같은 형식이어야 점수를 비교할 수 있다(#53 리뷰, C와 합의).
- **주의할 점**: 문장 비교만으로는 "말투만 바꾼 같은 질문"과 "같은 틀에 종목·사건만 바꾼 다른 질문"을 가를 수 없어서, **거의 같은 문장만** 잡기로 했다(B 결정). 2026-11-02 예시로 잰 점수(ratio / token_set_ratio): 완전히 같음 100/100, 같은 틀 다른 종목 86/93, 같은 틀 다른 사건 86/84(짧은 질문은 90을 넘을 수 있음: "금리 동결 이후 어느 쪽 흐름을 더 지켜볼까요?"와 "금리 인하 이후 …"는 ratio 92), 말투만 다른 같은 질문 75/77, 짧은 질문이 긴 질문에 포함 56/100, 전혀 다름 33/28. 기술확정안의 `token_set_ratio`는 포함 관계면 100이라 다른 문제를 잘못 거를 수 있어 쓰지 않았다. 판단해보기 질문은 틀이 비슷해 다른 사건도 걸리므로 C가 빼고 넘긴다. RapidFuzz는 `pyproject.toml`에 아직 없어 A에게 추가를 요청했다. 함수 안에서 불러오므로 설치 전에도 다른 검사는 쓸 수 있다.
- **테스트**: `python -m pytest tests/test_duplicates.py -q` (같은 문장·문장부호만 다름은 걸림, 같은 틀 다른 종목·사건, 포함 관계, 다른 질문은 통과, 기준값 조절, 빈 입력, 여러 개 보고).
