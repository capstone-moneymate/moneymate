# worker/collectors/sec_numbers.py

- **한 줄 설명**: 미국 8-K 실적 공시(Item 2.02)에 분기 매출·순이익·주당순이익과 전년동기 대비 증감률·방향을 붙여 `raw_sources.numbers`를 채운다. 8-K는 제목만 있어서 탭 2 이유가 "공시 내용은 알 수 없지만"이라고만 썼다(2026-11-16 2분기 20종목).
- **입력**: `raw_sources`의 `sec_8k`·`earnings` 줄(티커, 발표일). SEC `company_tickers.json`(티커 → CIK)과 `data.sec.gov/api/xbrl/companyfacts/CIK##########.json`(회사가 10-Q·10-K로 낸 XBRL 재무 값). `.env`의 `EDGAR_IDENTITY`를 User-Agent로 보낸다. edgartools를 쓰지 않아 Windows에서도 돈다(pyarrow DLL 차단과 무관).
- **하는 일**: ① 8-K 발표일보다 앞에 끝난 분기 중 가장 최근, 발표일과 75일 이내인 분기를 고른다(없으면 빈 값: 10-Q가 아직 안 나온 경우) ② 분기 값은 기간이 80~100일인 XBRL 값(같은 기간이 여러 번 접수됐으면 가장 늦게 접수된 값). 회계연도 4분기는 SEC에 분기 값이 없어 연간 − 같은 시작일의 9개월 누계로 계산한다. 주당순이익은 분기마다 주식 수가 달라 빼면 맞지 않아서 그 분기에는 넣지 않는다 ③ 전년동기는 분기 끝날 1년 전(±10일)에 끝난 분기 ④ 증감률은 코드가 계산(소수 첫째 자리). 부호가 바뀌면 % 대신 흑자전환·적자전환, 둘 다 음수면 적자지속(DART numbers와 같은 말) ⑤ 매출 태그는 RevenueFromContractWithCustomerExcludingAssessedTax → Revenues → SalesRevenueNet 순서로 그 분기 값이 있는 것.
- **출력**: `{"실적기간": "2026-01-01~2026-03-31", "단위": "백만달러 (주당순이익은 달러)", "매출액": 82886, "매출액 전년동기": 70066, "매출액 전년동기대비(%)": 18.3, "매출액 전년동기대비 방향": "증가", "당기순이익" …, "주당순이익(희석)" …}`. `python -m collectors.sec_numbers [--save] [--all]`은 numbers가 빈 8-K 실적 줄을 채운다(`--all`은 다시 계산). `sources.fetch_sec_8k`도 수집할 때 `fill_sec_earnings`로 같은 값을 붙인다.
- **주의할 점**: 값은 10-Q·10-K의 XBRL이라 8-K 보도자료와 같은 숫자지만 10-Q 접수가 8-K보다 며칠 늦을 수 있다(그동안은 비어 있다 → 나중에 `--save`로 채운다). 해외 발행사(TSM·ARM 등)는 8-K·10-Q 대신 6-K·20-F라 대상이 아니다. 회사가 매출 태그를 다르게 쓰면 매출이 빠질 수 있다(LITE는 순이익·주당순이익만 나옴). SEC 호출은 티커마다 1번(초당 10회 제한 안).
- **테스트**: `cd worker && python -m pytest tests/test_sec_numbers.py -q` (가짜 companyfacts 손계산: 82,886 ÷ 70,066 − 1 = 18.3%, 순이익 -50 → 31,778 흑자전환, 4분기 331,839 − 241,832 = 90,007·주당순이익 없음, 늦게 접수된 값 우선, 75일 넘으면 빈 값, 매출 태그 대체, 흑자·적자 전환, 티커마다 한 번만 받기). `tests/test_sources.py`: 계약 공시는 안 채우고 SEC 오류는 비워 둠. 2026-11-16 실제 실행: 2분기 겹침 20종목의 8-K 실적 51건 모두 채움(MSFT 4/29 매출 82,886 +18.3%, NET 적자지속, PANW 적자전환, MU 9/30은 4분기라 주당순이익 없음).
