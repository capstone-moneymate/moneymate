# worker/eval/bank.py

- **한 줄 설명**: 1-5 퀴즈 은행 (#238). 가르치기용·마지막 시험용 퀴즈를 미리 만들어 두고 세 조건이 같이 꺼내 쓴다.
- **입력**: DB 의 개념 지도(`ConceptMap.from_db`), 카드 17·11 의 목표 개념(`card_targets`). 실행은 `cd worker && python -m eval.bank --per 3` (비용 약 $0.3).
- **하는 일**: 카드마다 범위(목표 + 선수 개념)의 개념 × 퀴즈 7종류 × `per`개를 `tutor.agent.make_quiz`(= `tutor.quiz.generate`: 모양 검사, 내용 검사 #234, 정답 위치 섞기)로 만든다. 헷갈리는 쌍·짝 맞추기는 이웃·짝 용어가 없으면 그 개념에서 건너뛴다. 마지막 시험용은 목표 개념마다 용어 뜻·사례 분류 2개씩 따로 만든다(가르칠 때 본 퀴즈를 시험에 다시 내면 외운 것을 잰다). `Draw`는 세션 하나가 (개념, 종류)마다 섞은 순서로 돌아가며 꺼낸다(`Session.quiz_maker` 모양). 없는 종류는 `QuizError`를 내서 에이전트가 다른 종류를 고르게 한다(실제 튜터와 같다).
- **출력**: `logs/eval/quiz_bank.json` (Git 에 안 올라감).
- **주의할 점**: 조건마다 퀴즈를 새로 만들면 퀴즈 난이도·오류가 조건마다 달라져 비교가 흐려지고 비용도 수백 번 든다. 은행은 한 번 만들면 그대로 쓴다(다시 만들면 결과가 달라진다).
- **테스트**: `cd worker && python -m pytest tests/test_eval.py -q` (꺼내기 순서가 돌아가고 없는 종류는 오류).
