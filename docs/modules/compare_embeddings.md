# worker/scripts/compare_embeddings.py

- **한 줄 설명**: 개념 지도 ③에 쓸 임베딩 모델과 기준값을 숫자로 고른다 (#198, 계획 9장 "임베딩 모델 미정").
- **입력**: `db/seeds/concepts.csv`의 이름·별칭 (개념 29개, 글 100개, 같은 개념 쌍 132개). 사람이 쓴 "같은 개념의 다른 표현" 묶음이라 정답으로 쓴다. 실행은 `cd worker && python -m scripts.compare_embeddings [모델 이름 ...]`. 모델을 안 쓰면 `term_groups.MODELS`의 후보 전부를 돌린다.
- **하는 일**: 모델마다 글 100개를 임베딩하고, 기준값 0.50~0.95(0.05 간격)로 묶어서 쌍 단위 정밀도·재현율·F1을 계산한다. F1이 가장 높은 기준값을 고르고, F1이 같으면 정밀도가 높은 쪽을 고른다. 그 기준값에서 잘못 합친 쌍과 놓친 쌍을 보여 준다.
- **출력**: 화면에 모델별 표와 요약을 출력하고, `logs/concept_map/embedding_compare.json`에 저장한다 (Git에 올라가지 않음).
- **주의할 점**: 기준값을 같은 정답 데이터로 고르므로 점수가 실제보다 좋게 나온다. 데이터가 작아서 따로 떼어 둘 여유가 없다. 그래서 이 점수는 모델끼리 비교하는 용도로만 쓴다. 정답 데이터에는 "기준금리 인상/인하/동결", "자사주 취득/소각", "HBM 공급/수요"처럼 글자는 비슷하고 뜻은 다른 반례가 들어 있어서, 잘못 합친 쌍 목록을 꼭 같이 본다.
- **테스트**: 점수 계산은 `tests/test_term_groups.py`의 `pair_scores` 손계산 테스트가 맡는다. 스크립트 자체는 실제 모델을 내려받아야 해서 pytest에 넣지 않았다.
