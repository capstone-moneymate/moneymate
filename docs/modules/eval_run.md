# worker/eval/run.py

- **한 줄 설명**: 1-5 실험을 돌리고 표·그래프를 만든다 (#238, 안 A: 카드 2장 × 학습자 4종류 × 반복 2번 = 칸마다 세션 16개).
- **입력**: 퀴즈 은행(`logs/eval/quiz_bank.json`), DB 개념 지도. 실행은 `cd worker && python -m eval.run`(비용 0, 고정·규칙만), `--agent --limit 1`(에이전트 세션 1개 시험), `--agent`(전체, 약 $10), `--bkt 처음,배울,실수`, `--report`(표만 다시).
- **하는 일**: 칸(설정 하나) = 설정 이름·교사·선수 효과·학습자 배울 확률·퀴즈 상한·과거 기록·학습자 실수·확신 잡음. main(선수 효과 1.0 / 0.5 / 0.0 × 고정·규칙·에이전트, 확신 없음: 세 조건이 같은 정보로), ablation(선수 효과 0.5 에서 에이전트 no_bkt·no_prereq), conf(선수 효과 0.5 에서 에이전트에 확신을 잡음 0 / 0.4 로 넣어 확신 효과의 범위), cap10(상한 10 × 세 조건), sens(학습자 배울 확률 0.1 / 0.5, 고정·규칙만), slip(학습자 실수 0.05 / 0.2 / 0.3, 고정·규칙만. BKT 는 실수 0.1 그대로: 시스템 가정과 실제 학습자가 다를 때). 과거 기록 없음은 고정·규칙만. BKT 값은 기본이 앱의 값이고 `--bkt 0.25,0.1,0.1` 로 바꿔 돌릴 수 있다(결과 줄에 남아 섞이지 않음). 같은 (카드, 학습자, 반복)이면 조건이 달라도 학습자 무작위 흐름이 같은 씨앗(`crc32`)에서 시작한다. 세션마다 결과를 한 줄씩 붙이고 이미 있는 세션은 건너뛴다.
- **출력**: `logs/eval/results.jsonl`(세션마다), `summary.md`·`summary.json`(칸별: 마지막 시험 정답률, 목표 개념 앎 비율, 목표 다 앎 비율, 낸 퀴즈 수, 다 알기까지 퀴즈 수), `summary.png`(main, 앱의 BKT 값: 선수 효과마다 조건별 목표 개념 앎 비율). 확신·BKT 값을 기록하기 전의 옛 줄은 읽지 않는다.
- **2026-11-25 비용 0 결과 (과거 기록 있음, 앱 BKT 0.25/0.2/0.1 #245)**: 목표 개념 앎 비율 고정 38% / 23% / 8%, 규칙 29% / 29% / 29% (선수 효과 1.0 / 0.5 / 0.0). 마지막 시험 정답률 고정 49% / 38% / 28%, 규칙 44% / 44% / 44%. 예전 값(0.3/0.1/0.1)과 비교하면 고정은 BKT를 안 써서 같고, 규칙은 앎 비율이 같고 시험 정답률만 42% → 44%로 올랐다. 학습자 실수가 BKT 가정(0.1)보다 크면(0.2·0.3) 규칙이 29% → 23%로 떨어진다(예전 값에서는 17%). 새 값에서는 그만큼 덜 떨어진다. 학습자 배울 확률 0.5에서는 규칙이 38% → 31%로 예전보다 낮다. 퀴즈 6개로 목표를 다 알게 된 세션은 거의 없다(고정 0~19%, 규칙 0%).
