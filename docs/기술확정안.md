## 인과 뼈대

인과 뼈대는 탭1 퀴즈 정답, 탭2 이유 설명, 탭3 인과 지도가 모두 함께 쓰는 데이터다. LLM이 뉴스마다 새로 만들면 같은 개념이 다른 이름(예: "금리 인하"와 "기준금리 하락")으로 생겨 지도에서 합쳐지지 않는다. 그래서 팀이 만든 사전을 기준으로 둔다.

| 단계           | 하는 일                                                                                                                                  | 담당            | 기술                                                                                        |
|----------------|------------------------------------------------------------------------------------------------------------------------------------------|-----------------|---------------------------------------------------------------------------------------------|
| 사전 구축      | 개념과 연결(올리는 힘 / 누르는 힘)을 미리 정의. LLM이 초안을 쓰고 팀이 검토                                                              | 팀              | concepts(id, name, theme, kind, aliases), causal_edges(from_concept, to_concept, 힘의 방향) |
| 뉴스 매칭      | 뉴스에서 시작 개념만 고름 (예: rate_hold 기준금리 동결)                                                                                  | LLM             | Claude API, 허용 concept_id 목록을 스키마의 enum으로                                        |
| 경로 찾기      | 시작 개념에서 연결을 따라 결과까지 탐색                                                                                                  | 코드            | networkx all_simple_paths                                                                   |
| 사전에 없을 때 | LLM이 new_concept_proposal로 제안만 함 → 2회 독립 추출이 같고 순환이 없으면 후보 → 팀 승인 후 추가. 추가 전에는 유형 1(뼈대 없음)로 출제 | LLM + 코드 + 팀 | Claude API, networkx is_directed_acyclic_graph                                              |
| 학습 기록      | 학습을 끝낸 카드의 개념·연결을 사용자 기록에 반영. 인과 지도 = 내가 학습한 개념·연결의 합집합                                            | 코드            | user_concepts(user_id, concept_id, correct, total)                                          |

- 뼈대는 원리(힘)만 가지고, 결과는 여러 갈래가 가능하다. 정답이 있는 것은 "이 힘이 어느 방향으로 미는가"까지다.

- 2회 추출이 일치해도 둘 다 틀릴 수 있어, 바로 정답으로 쓰지 않고 팀 승인을 거친다.

- 사전 규모: 프로토타입 3개 테마(금리, AI·반도체, 차트 읽기) 개념 17개에서 시작해 30~50개까지.

- 개념과 종목(티커)을 잇는 매핑 테이블로 탭2 종목 상세의 "내 지도에 있어요"와 연결한다.

## 문제 생성·검증

카드뉴스와 문제는 하루 한 번 미리 만들어 DB에 저장하고, 사용자는 읽기만 한다. 코드가 숫자를 먼저 계산해 넘기고 Claude는 문장만 쓴다. 요청 1번에 응답 1번이라 디버깅이 쉽고, 안정되면 Batch API(표준 요금의 50%)로 바꿀 수 있다.

| 단계                    | 하는 일                                                                              | 담당       | 기술                                                                  |
|-------------------------|--------------------------------------------------------------------------------------|------------|-----------------------------------------------------------------------|
| 1\. 수집                | 뉴스, 가격, 13F, 액티브 ETF 보유 내역                                                | 코드       | 데이터 수집 표 참고                                                   |
| 2\. 선별                | 중복 제거, 중요도 점수(w₁ × 매체 수 + w₂ × \|관련 종목 등락률\|) 상위 3건            | 코드       | RapidFuzz(제목 유사도), pandas                                        |
| 3\. 겹침 계산           | 큰손·ETF 보유 수량 변화와 방향 판정. ETF는 분기 말 대비 추세 기준, 자금 유입 보정 후 | 코드       | pandas (compute/overlap.py)                                           |
| 4\. 유형 분류·뼈대 매칭 | 뉴스 유형(1/2/3)과 시작 개념 고르기 → 경로 탐색                                      | LLM + 코드 | Claude Haiku, networkx                                                |
| 5\. 정답 계산           | 지표, 거래량 상위일, 기간 수익률 계산                                                | 코드       | pandas-ta-classic (df.ta.rsi() 등)                                    |
| 6\. 출제                | 4·5의 숫자와 허용 개념 id를 프롬프트에 넣고 카드뉴스·문제·해설을 JSON으로 받음       | LLM        | anthropic SDK messages.create + tool_choice(JSON 강제), Claude Sonnet |
| 7\. 검증                | 아래 표. 실패하면 6으로 돌아가 재생성 (최대 3회)                                     | 코드       | validate/validators.py                                                |
| 8\. 게시                | status='pending'으로 저장 → 팀 확인 후 published                                     | 팀         | psycopg 3 → PostgreSQL                                                |

| 검증            | 방법                                                                 | 기술                             |
|-----------------|----------------------------------------------------------------------|----------------------------------|
| 형식            | JSON 구조·필수 필드 확인                                             | pydantic (model_validate)        |
| 정답            | 코드가 다시 계산한 값과 LLM 정답 비교. 인과 순서는 사전 경로와 비교  | pandas-ta-classic, networkx      |
| 금지 표현       | 매수·매도 권유, 예측 표현. 걸린 표현은 목록에 계속 추가              | Python re                        |
| 중복            | 이미 출제한 문제와 문장 유사도 비교                                  | RapidFuzz (fuzz.token_set_ratio) |
| 근거 날짜 (탭2) | 출력의 근거 뉴스 번호가 입력에 있었는지, 날짜가 공시 기준일 이전인지 | Python                           |

- 차트 읽기의 "비슷했던 과거의 날"은 자동으로 찾지 않고, 팀이 만든 이벤트 날짜표(금리 동결일, 급등락일 등 20~30개)에서 고른다.

- 모델은 일에 따라 나눈다. 분류·매칭은 Haiku, 출제·채점은 Sonnet.

- 호출마다 resp.usage를 llm_cost_log에 남겨 문제 1개당 비용을 잰다. 하루 처리 뉴스 수·재시도·월 한도에 상한을 둔다.

- 독립 풀이(LLM이 자기 문제를 다시 풀어 비교)는 시간이 남으면 추가한다.

### 루브릭

| 기준 | 배점 | 보는 것                                                               | 담당 | 근거                                |
|------|------|-----------------------------------------------------------------------|------|-------------------------------------|
| 증거 | 2    | 뉴스 속 사실·숫자를 근거로 썼는가. 출제 때 만든 핵심 사실 목록과 대조 | 코드 | CER (McNeill et al., 2006)          |
| 추론 | 3    | 개념을 사슬처럼 이어 판단까지 연결했는가                              | LLM  | SOLO (Biggs & Collis, 1982)         |
| 반박 | 2    | 다른 힘이나 위험을 구체적으로 고려했는가                              | LLM  | Toulmin 반박 (Osborne et al., 2004) |

- 선택(추가매수, 관망 등) 자체는 채점하지 않는다. 근거 작성은 필수다.

- LLM에는 기준별 점수 설명과 점수별 예시 답안을 함께 준다.

- 피드백 문장에 금지 표현이 있으면 고정 문구("근거 있는 선택이었어요 / 이런 경우도 생길 수 있어요")로 대체한다.

- 사용자별 하루 호출 횟수를 제한하고, 같은 답안은 해시로 결과를 재사용한다.

### 채점 신뢰도 확인

| 단계            | 하는 일                                                              | 기술                                                |
|-----------------|----------------------------------------------------------------------|-----------------------------------------------------|
| 1\. 답안 모으기 | 판단 근거 답안 40개 안팎 (파일럿 사용자 + 팀이 수준별로 쓴 답안)     | PostgreSQL에서 CSV로 추출                           |
| 2\. 사람 채점   | 팀원 3명이 따로 채점 → 세 사람 간 일치도 확인 후 합의 점수 확정      | statsmodels fleiss_kappa                            |
| 3\. LLM 비교    | 합의 점수와 LLM 점수의 일치도를 기준별로 계산                        | scikit-learn cohen_kappa_score(weights="quadratic") |
| 4\. 기준        | κ 0.6 이상이면 사용. 미만이면 점수 설명·예시 답안을 고치고 다시 비교 | \-                                                  |

κ 0.6은 Landis & Koch(1977)에서 "상당한 일치"가 시작하는 값이다.

## 데이터·구조·스택

### 데이터 수집

| 데이터           | 기술                                                                                                                                                            | 주기                                 |
|------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------|
| 가격·지수        | FinanceDataReader (fdr.DataReader, KS11·KQ11·IXIC 등). 실패하면 yfinance                                                                                        | 매일                                 |
| 13F (큰손 4명)   | edgartools (set_identity 필수, get_filings(form="13F-HR"), compare_holdings()) + OpenFIGI API v3 (ID_CUSIP → 티커, cusip_map 테이블에 캐시)                     | 분기 1회                             |
| 액티브 ETF (2개) | pykrx stock.get_etf_portfolio_deposit_file → 안 되면 운용사 구성종목 파일 다운로드(requests, 막히면 Playwright) → 그래도 안 되면 팀원이 매일 파일을 받는 반자동 | 매일                                 |
| 뉴스             | 네이버 검색 API(뉴스), 감시 키워드 3종(종목·섹터·거시). 제목·URL·언론사·시각만 저장                                                                             | 하루 4회(12:00, 16:00, 23:30, 08:00) |

- 보유 변화는 보유 수량 기준이다 (13F는 SharesPrnAmount). 옵션(PUT/CALL)과 채권(Principal)은 뺀다.

- "늘림"은 1주만 늘어도 잡히므로 +N% 이상으로 기준을 둔다 (2주차 확정).

- 13F는 분기 종료 후 45일 안에 공시되어 3분기분은 11월 중순에 나온다. 개발은 2분기(6/30) 데이터로 하고 같은 코드로 갱신한다.

- ETF는 분기 말 대비 변화(추세)와 전 거래일 대비 변화(어제)를 둘 다 저장한다. 스냅샷은 지난 날짜를 못 구할 수 있어 지금부터 매일 쌓고, 9/30 보유 내역 확보 방법을 1주차에 먼저 확인한다.

- ETF 자금 유입 보정: 돈이 들어오면 모든 종목 수량이 같이 늘기 때문에, 종목별 수량 변화율에서 ETF 전체 종목 변화율의 중앙값을 뺀다.

- 저작권: 기사 본문은 저장·게시하지 않고, Claude가 쓴 요약 + 원문 링크로 보여준다.

- 시간대는 Asia/Seoul 기준으로 두고, 미국장 날짜와의 차이를 코드에 명시한다.

### 구조

Python 워커가 계산하고 DB에 쓰며, Node 서버는 DB에서 읽기만 한다. 사용자 요청으로 LLM을 부르는 것은 판단 근거 채점과 주관식 피드백뿐이다.

| 폴더          | 역할                                                                                                                                                  | 기술                                                                                                                                                    |
|---------------|-------------------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------|
| web           | 탭 3개 화면 (모바일 웹 390×844). 처음엔 목 데이터로 화면 완성                                                                                         | React, TypeScript, React Router, TanStack Query, lightweight-charts, React Flow (@xyflow/react)                                                         |
| server        | DB 읽기 API, 답안 저장, 채점 요청 전달                                                                                                                | Node.js LTS, Express, node-postgres(pg)                                                                                                                 |
| worker        | 수집(collectors/), 겹침·지표 계산(compute/), 출제·채점(generate/), 검증(validate/), 매일 실행(run_daily.py)                                           | Python 3.12, finance-datareader, edgartools, pykrx, pandas, pandas-ta-classic, anthropic, pydantic, networkx, RapidFuzz, psycopg 3, APScheduler, pytest |
| tradingagents | 탭1 해설용 분석 리포트만 생성 (매매 결론 제외)                                                                                                        | TradingAgents, 별도 Python 3.12 venv, subprocess로 호출                                                                                                 |
| DB            | raw_news, prices, holdings_13f, holdings_etf, overlap_results, cards, steps, concepts, causal_edges, users, user_answers, user_concepts, llm_cost_log | PostgreSQL (Docker Compose)                                                                                                                             |

- API 키는 .env에만 두고 .gitignore에 추가한다. Anthropic Console에서 월 사용 한도부터 설정한다.

- 개발은 "탭1 한 사이클 → 탭2 겹침 한 줄 → 탭3 개념 몇 개" 순서로 얇게 끝까지 먼저 만든 뒤 넓힌다.

## TradingAgents

탭1 해설 재료(기술적 지표 해석, 낙관·비관 토론)로만 쓰고, 실제 사용은 마지막 단계의 1주 시험으로 정한다. 쓰지 않아도 나머지 구조는 그대로 동작한다.

README에 따르면 뉴스·소셜 데이터는 분석 날짜를 과거로 고정해도 현재 기준 내용을 가져온다. 그래서 "공시 기준일 이전 뉴스만" 규칙을 지킬 수 없어 탭2 "가능한 이유"에는 쓰지 않는다. 탭2 근거는 우리 뉴스 DB에서 날짜로 거른 뉴스만 번호를 붙여 Claude에 넘긴다.

| 시험 항목 | 통과 기준                                                                | 설정·기술                                                                                   |
|-----------|--------------------------------------------------------------------------|---------------------------------------------------------------------------------------------|
| 연결      | Claude로 분석 1회 완주                                                   | llm_provider="anthropic", deep_think_llm·quick_think_llm은 라이브러리 모델 목록에 있는 모델 |
| 비용·시간 | 종목 1개 분석이 월 한도 안에서 매일 돌 수 있음                           | max_debate_rounds=1, max_risk_discuss_rounds, --analysts market,news                        |
| 한국어    | 해설 재료로 쓸 만한 품질                                                 | output_language                                                                             |
| 저장      | 분석 리포트 + 낙관·비관 토론만 JSON으로 저장, 매매 결론(Buy~Sell)은 버림 | final_state.keys()로 필드 확인 후 추출, 쓰기 경로는 TRADINGAGENTS\_\* 환경변수              |
| 버전      | 두 검토의 버전이 다름 (0.6.0 / v0.3.1)                                   | 설치 후 pip show tradingagents와 pyproject.toml로 확인해 버전 고정                          |
