## B — ETF 구성종목 / 9/30 확인

확인 방법: pykrx `stock.get_etf_portfolio_deposit_file(code, 날짜)`로 구성종목(PDF) 조회. `worker/scripts/check_etf_holdings.py`

| ETF | 코드 | 10/8 | 9/30 | 6/30 | 주식이 아닌 줄 | 수량 |
|---|---|---|---|---|---|---|
| TIME 미국나스닥100액티브 | `426030` | ☑ 44줄 | ☑ 44줄 | ☑ 47줄 | 원화현금 `010010`, 설정현금액 `H00000`, 나스닥100 선물(`NQZ6` 등) | 정수 (예: NVIDIA 239) |
| KoAct 미국나스닥성장기업액티브 | `0015B0` | ☑ 47줄 | ☑ 46줄 | ☑ 59줄 | 원화현금 `010010`, 설정현금액 `H00000` | **소수** (예: NVIDIA 99.88) |

- 확인일 2026-10-11, pykrx 1.2.9. 결과: 두 ETF 모두 오늘·9/30·6/30 조회 성공.
- 막힌 점: **KRX 정보데이터시스템이 로그인을 요구한다.** 로그인 없이는 빈 결과. data.krx.co.kr 일반 회원가입(아이디·비밀번호) 후 `.env`에 `KRX_ID`, `KRX_PW`를 넣으면 pykrx가 자동 로그인한다. 간편 로그인(네이버 등) 계정은 비밀번호가 없어 쓸 수 없다.
- **구성종목 코드는 미국 티커(NVDA)가 아니다.** `7066G1`(NVIDIA), `378331`(Apple), `8160R1`(Tesla)처럼 6자리이며, **CUSIP 9자리의 2~7번째 글자(맨 앞 1글자와 맨 뒤 2글자를 뺀 것)와 같다** (B가 직접 확인).
  - Apple `037833100` → `378331` ✅ (버크셔 13F-HR 원본 INFORMATION TABLE에서 확인)
  - Tesla `88160R101` → `8160R1` ✅
  - NVIDIA `67066G104` → `7066G1` ✅
  - 따라서 A의 13F `cusip`과 이어 붙일 수 있다. 다만 맨 앞 글자가 빠져 있어 드물게 다른 회사 CUSIP과 6자리가 겹칠 수 있으니, 매칭 결과는 종목명으로 한 번 눈으로 확인한다.
- 종목명 표기가 ETF마다 다르다 (`NVIDIA CORP` / `NVIDIA Corp`, `TESLA INC` / `TESLA MOTORS`). 이름으로 맞추지 말고 코드로 맞춘다.
- **수량은 ETF 전체 보유량이 아니라 설정 단위(1CU)당 구성 수량이다** (B가 직접 확인함).
  - TIME: 운용사 PDF 화면에 "구성종목(PDF) 내역은 ETF 최소 설정단위인 1CU를 기준으로 작성" 명시
  - KoAct: 설정단위 50,000좌 × 기준가 19,775원(10/8 화면) ≈ 9.89억 원 → 10/8 PDF의 설정현금액 9.92억 원과 거의 일치. 운용사 사이트의 NVIDIA 수량 100도 pykrx 값(99.88)과 맞다
  - 1CU 기준 수량은 자금이 들어와도 같이 늘지 않으므로 **자금 유입 보정(중앙값 빼기)이 필요 없다.**

결과 3줄 요약:
1. 두 ETF 모두 pykrx로 오늘·9/30·6/30 구성종목을 받을 수 있다 (KRX 로그인 필요). **9/30을 구했으므로 추세 기준일은 9/30으로 간다.**
2. KoAct 코드는 `0015B0`(영문 섞인 코드), 구성종목 코드는 CUSIP 일부, KoAct 수량은 소수다 → 스키마·정규화 함수 수정이 필요하다 (아래 싱크 안건).
3. 현금·선물 줄은 저장하지 않고 주식만 저장한다.

싱크 안건 (B → A, A의 안건 번호 기준):
- **B1 (구성종목 코드)**: 받은 코드가 티커가 아니라 CUSIP 일부라서 지금 `ticker NOT NULL`에 NVDA를 바로 넣을 수 없다. → `raw_code`(받은 그대로) 컬럼을 추가하고 `ticker`는 변환 후 채우는(못 찾으면 NULL) 방향을 제안. 변환은 13F `cusip`의 2~7번째 글자로 맞추거나 OpenFIGI 사용
- **B2 (현금·선물)**: 주식만 저장 (`asset_type` 컬럼 없이). 원화현금 `010010`, 설정현금액 `H00000`, 선물(코드 6자리 아님)은 빼고 저장
- **수량 타입**: KoAct 수량이 소수라 `holdings_etf.shares` BIGINT에 못 담는다. conventions.md 1장 "수량: 주식 수 BIGINT" 규칙과도 걸린다. → ETF만 `NUMERIC`으로 바꾸는 마이그레이션 + 규칙에 "ETF 수량은 1CU 기준 소수 가능" 추가 요청
- **ETF 코드 형식**: `normalize_kr_code`가 숫자만 허용해서 `0015B0`을 거부한다 → 영문 대문자가 섞인 6자리도 허용 요청 (conventions.md 1장 "6자리 코드 문자열"은 그대로 맞음)
- **자금 유입 보정**: 수량이 1CU 기준임을 확인했으므로 `trend_adj_pct`(중앙값 빼기) 제거를 제안한다. 기술확정안의 "ETF 자금 유입 보정"과 conventions.md P3(방향 판정에 `trend_adj_pct` 사용)도 함께 수정 필요. 단, 운용사가 설정단위를 바꾸면 전 종목이 같은 비율로 변하므로 수집기에서 이 경우 경고를 띄운다

## C — 뉴스 API 샘플 20건 / Claude 호출 1회 비용

### 네이버 검색 API (뉴스)

확인 방법: `cd worker && python scripts/check_naver_news.py` → 감시 키워드 3개(엔비디아·반도체·기준금리)로 20건, `logs/naver_news_sample.json` 에 저장

- **검색 API가 네이버 개발자센터에서 NAVER API HUB(네이버 클라우드 플랫폼)로 옮겨갔다.** 개발자센터 "사용 API" 목록에 검색이 없다. 개발자센터 키는 못 쓰고, NCP 콘솔 → NAVER API HUB → Application 등록으로 새로 발급한다 ([이관 가이드](https://guide.ncloud-docs.com/docs/apihub-migration))
  - 주소: `https://naverapihub.apigw.ntruss.com/search/v1/news`
  - 헤더: `X-NCP-APIGW-API-KEY-ID`(Client ID), `X-NCP-APIGW-API-KEY`(Client Secret). `.env` 키 이름은 `NAVER_CLIENT_ID/SECRET` 그대로
  - 한도: 기간 한정 무료(유료 전환은 사전 공지), NAVER 검색 묶음 합계 월 775,000건, 키당 50 RPS. 하루 4회 수집이면 충분
- 막힌 점: **NCP 가입 시 결제 수단 등록이 필수.** 무료 기간에는 한도 초과 시 과금이 아니라 429로 막히지만, 유료 전환 뒤에는 과금될 수 있다
- 응답 필드: `title`, `originallink`, `link`, `description`, `pubDate`(`Mon, 12 Oct 2026 17:20:00 +0900` 형식). 언론사 이름 필드가 없어 `raw_news.press` 는 `originallink` 도메인(예: `www.aitimes.com`)으로 매핑해야 한다. 제목·요약에 `<b>` 태그와 HTML 엔티티가 섞여 와서 저장 전에 지운다
- 확인일 2026-10-12, 결과: **성공.** 3개 키워드 × 7건 → 20건, 원문 링크 20건 모두 있음(네이버 뉴스 링크 6건)
  - 제목 평균 36자(25~45), **요약 평균 123자(116~135), 20건 중 19건이 `...`로 잘림**
  - 요약은 기사 리드가 아니라 **검색어 주변 문장 발췌**다. 예: "삼성전자, 역대급 실적에도 주가 하락" 기사의 요약이 본론과 무관한 엔비디아 젯슨 실험 문장
  - **검색어가 지나가듯 나온 기사도 잡힌다.** `반도체`로 LH 집값·한전채·쿠팡 기사가 나옴 → news_select.py에서 관련도 거르기 필요
  - **같은 기사가 다른 키워드로 중복 수집된다** (한은 총재 국감 기사가 `반도체`·`기준금리` 둘 다) → url UNIQUE로 막히지만 keyword가 하나만 남음
- (제안) 결론: 제목·요약은 **선별과 유형 분류(Haiku) 재료로는 충분**하지만, 기사 1건의 요약만으로는 **카드뉴스 3장(무슨 일 → 포인트 → 결론) 재료로는 부족**해 보인다. → 싱크 안건 C2
