# 머니메이트 추가 구현 계획 (SW 차별점)

2026-11-23 작성 · 마감 12/4 · 2명 분담 (사람1, 사람2)

> **새 대화창에서 이어서 작업할 때는 이 문서부터 읽는다.** 맨 아래 "진행 체크리스트"에서 어디까지 했는지 확인한다.

---

## 1. 왜 하는가

11/21 교수님 면담에서 받은 질문:

- "SW적으로 차별점이 뭐냐 / 그냥 퀴즈 아니냐"
- "순서대로 실행하는 건 에이전트가 아니라 자동화 아니냐"
- "있는 거 갖다 쓴 거 아니냐"
- "평가 기준을 너네가 정했다 (순환 평가)"

답하려는 방향: **사용자마다 다르게 가르치는 학습 엔진**을 만들고, **우리가 직접 한 실험 숫자**로 효과를 보인다.

- 개념 지도를 LLM으로 자동으로 만들고 (손으로 쓴 사전 아님)
- 사용자가 각 개념을 얼마나 아는지 확률로 추적하고 (BKT)
- 튜터 에이전트가 그 상태를 보고 다음에 무엇을 가르칠지 스스로 고르고
- 잊을 때쯤 복습시키고 (FSRS)
- "안다고 생각함"과 "실제로 앎"의 차이를 보여 준다 (확신 보정)
- 가상 학습자 실험 + 실제 사용자의 이전 기록 비교(고스트)로 효과를 보인다

탭 1 인과 학습(검증기, Datalog)은 **그대로 유지**한다. 이번 작업은 그 위에 얹는 것이다.

[사람1] 튜터 에이전트 ◀── get_mastery() ── [사람2] BKT 지식 상태

## 4. 사람1: "무엇을 가르칠지"

### 1-1. 개념 지도 자동 생성 (`worker/concepts/`)
- 카드의 concept 단계 용어(terms)와 1차 자료에서 LLM이 용어를 뽑는다
- 로컬 한국어 임베딩으로 같은 뜻의 용어를 하나로 묶는다 ("EPS" = "주당순이익")
- 개념 쌍마다 "A를 알아야 B를 이해할 수 있나?"를 LLM에 **독립적으로 여러 번** 묻고 다수결로 선수 관계를 정한다 (proposals.py의 "2회 일치" 방식을 넓힌 것)
- 완료 기준: 개념 노드와 선수 관계가 DB에 저장되고, 몇 개가 만들어졌는지 로그로 나온다

### 1-2. 선수 관계 순환 검사 (`worker/concepts/prereq.dl`)
- 기존 Datalog 엔진(datalog.py)을 그대로 쓴다. 인과 규칙과 같은 방식으로 `prereq` 도달 관계를 계산하고, 자기 자신에게 돌아오면 순환
- 순환이 생기면 표가 가장 적은 연결을 뺀다
- `ready(U, C)` 규칙: 선수 개념을 모두 알면 C를 배울 준비가 됨 (부정 `!` 사용)
- 완료 기준: pytest (손으로 만든 작은 그래프에서 순환 검출, ready 결과가 손계산과 같음)

### 1-3. 튜터 에이전트 (`worker/tutor/` 새로)
- 도구:
  - `ready_concepts(user)`: 배울 준비가 된 개념 + 알 확률
  - `ask_quiz(concept, 종류)`: 그 개념 퀴즈를 아래 종류 중 하나로 생성 (기존 출제 재사용)
  - `explain(concept, 방식)`: 짧은 설명 (예시 위주 / 정의 위주)
  - `go_main()`: 개념 단계를 끝내고 뉴스 본 문제로
- 에이전트가 도구 결과를 보고 다음 행동을 스스로 고른다 (고정 순서 아님). 이게 "자동화가 아니라 에이전트"의 근거 (Anthropic, *Building effective agents*, 2024의 워크플로/에이전트 구분)
- 개념 단계 퀴즈 종류 (화면 2개로 7종류):

  | 화면 | 종류 | 확인하는 것 | 찍어서 맞힐 확률 |
  | :--- | :--- | :--- | :--- |
  | A. 보기 고르기 | 용어 뜻 고르기 | 뜻 | 보기 수에 따라 (3지선다 약 33%) |
  | A | 헷갈리는 쌍 구분 ("PER일까 PBR일까") | 비슷한 개념 구분. 쌍은 개념 지도에서 임베딩이 가까운 개념끼리 자동으로 | 50% |
  | A | 틀린 설명 고르기 | 오개념 | 약 33% |
  | A | O/X | 빠른 확인, 복습 워밍업 | 50% |
  | B. 칩을 칸에 넣기 | 단어 칩 빈칸 | 문장 속 쓰임 | 칩 4개·빈칸 2개면 약 8% |
  | B | 짝 맞추기 (용어 ↔ 뜻) | 여러 용어 구분 | 3쌍이면 약 17% |
  | B | 사례 분류 (사례를 바구니로) | 상황에 적용 | 사례 4개·바구니 2개면 약 6% |

- **에이전트가 종류를 고르는 근거**: 종류마다 확인하는 것과 찍어서 맞힐 확률이 다르다. 예) 처음 보는 개념 → 용어 뜻, 헷갈리는 이웃이 있음 → 헷갈리는 쌍, 긴가민가 → 찍기 어려운 칩 빈칸·사례 분류, 확신했는데 틀렸던 개념 → 틀린 설명 고르기, 거의 앎 → O/X로 빠르게 확인. 찍어서 맞힐 확률은 코드가 계산해 BKT 추측 확률로 넘긴다
- 시간 남으면 추가할 후보: 간단 계산 (정답을 코드가 계산, 찍기 거의 불가능, 공식이 있는 개념만), 징검다리
- 최대 단계 수, 비용 상한을 둔다
- BKT가 아직 없으면 `get_mastery`가 가짜 값을 돌려주게 하고 먼저 개발
- 완료 기준: 서로 다른 지식 상태의 사용자 2명에게 서로 다른 순서를 고르는 로그

### 1-4. 과거 뉴스 다시 풀기 (`web/src/pages/tab1/`, 뉴스·답안 API)
- **이미 있는 것 (#194/#195)**: 학습 달력 날짜 카드의 "퀴즈 다시 풀기"(`/news/:id`)는 카드뉴스부터 처음 상태로 새로 채점한다. "풀었던 내용 보기"(`?review=날짜`)는 그날 마지막 답을 읽기 전용으로 보여 준다
- **남은 것**: 다시 푼 답을 "몇 번째 시도"로 구분해서 저장한다 (지금은 날짜로만 구분돼서 같은 날 두 번 풀면 마지막 답만 보임, attempt_no + 1)
- 이전에 푼 기록이 있으면 과거 뉴스에서 들어와도 고스트 모드로 연다 (2-6). 이 재도전 기록이 고스트 비교 데이터가 된다
- 완료 기준: 같은 카드를 같은 날 두 번 풀어도 시도별 답 기록이 따로 남는다

### 1-5. 가상 학습자 평가 (`worker/eval/`)
- LLM 가상 학습자에게 **숨긴 정답 지식 상태**를 준다 (예: "금리는 알고 EPS는 모름"). 숨긴 상태가 있으니 "기준을 우리가 정했다"는 비판을 피한다
- 비교 조건: ① 고정 순서 ② 규칙만 (BKT 낮은 순) ③ 에이전트
- 제거 실험: 에이전트에서 BKT 빼기 / 선수 관계 빼기 / 확신 빼기
- 지표: 목표 개념을 다 익힐 때까지 걸린 문제 수, 마지막 시험 정답률
- **12/2 전에 시작한다.** 결과가 안 좋아도 원인 분석이 발표 내용이 된다
- 완료 기준: 조건별 표 1개 + 그래프 1개

## 5. 사람2: "학습자 상태"

### 2-1. 답 기록 확장 (`db/migrations/009_...sql`, `server/`)
- user_answers에 확신(애매/확신, 판단해보기는 비움), 응답 시간(ms), 답 변경 횟수, 몇 번째 시도 추가
- DB 마이그레이션은 **사람2가 혼자 관리**한다. 사람1이 필요한 테이블(개념 노드, 선수 관계)도 사람2가 같은 파일에 넣는다

### 2-2. 애매/확신 답 화면 (`web/`)
- 모든 문제(판단해보기 제외)에서 답을 고른 뒤 누르던 [확인]을 [애매해요] [확신해요]로 바꾼다. 누른 뒤 정답·해설이 나온다
- 판단해보기는 원래대로 [확인]
- 문제가 보인 시각 ~ 제출 시각, 답을 바꾼 횟수를 같이 보낸다

### 2-3. BKT 지식 상태
- 답이 들어올 때마다 개념별 알 확률을 갱신 (베이즈 갱신 → 배움 반영)
- 파라미터: 추측은 문제 형식으로 계산 (4지선다 0.25, O/X 0.5), 실수는 0.1 이하, 처음 알 확률·배울 확률은 민감도 분석. 데이터가 쌓이면 pyBKT로 학습
- `get_mastery(user_id) → {개념: 알 확률}` 을 사람1에게 제공
- 완료 기준: pytest (처음 0.3, 추측 0.25, 실수 0.1, 배움 0.1에서 맞힘 → 약 0.65, 틀림 → 약 0.15)

### 2-4. FSRS 복습 일정
- 개념별 안정도·난이도, 다음 복습일 (기억 확률 90% 시점)
- 자동 평가: 정답(주 신호) + 확신 + 보정한 응답 시간
- 하루 복습 상한, 기억 확률 낮은 순. 복습 단위는 개념이고 문제는 매번 새로

### 2-5. 확신 보정
- 확신 버튼을 확률로 바꿈 (예: 확신해요 = 0.9, 애매해요 = 0.6)
  - **이 값은 사람2가 문헌을 찾아서 근거와 함께 정한다.** 발표에서 "그 숫자는 어디서 나왔냐"는 질문이 반드시 나오므로, 팀이 임의로 정한 값을 쓰지 않는다
  - 찾아볼 것: 확신을 2단계(또는 소수 단계)로 받았을 때 확률로 바꾸는 방법, 메타인지 보정(metacognitive calibration) 측정 방법
  - 출발점 후보 (원문 확인 필요): Lichtenstein, Fischhoff & Phillips (1982) 확률 보정 연구 / Schraw (2009) 메타인지 모니터링 측정 지표 비교
  - 숫자로 바꾸기 어려우면 대안: 확률 값 없이 **"확신해요 답의 정답률 − 애매해요 답의 정답률"**(구분 능력)처럼 두 그룹의 실제 정답률만 비교하는 지표도 있다. 어떤 지표를 쓰든 근거 문헌을 문서에 적는다
- Brier 점수 (p − 결과)², 답이 20~30개 쌓이면 보정 곡선 (확률 값을 쓰는 경우)
- 2×2 표: 실제로 앎(BKT) × 안다고 생각함(확신). **"확신했는데 틀림" 칸이 가장 위험** → 복습 우선순위 맨 앞 (과잉 수정 효과)

### 2-6. 고스트 비교 (학습 이력)
- 카트라이더 고스트처럼 **이전의 나와 지금의 나**를 나란히 보여 준다
- **언제 고스트가 되나**: 이 카드를 이전에 푼 기록(학습 이력)이 있으면 어디서 들어오든(과거 뉴스, 학습 달력) 고스트. 처음 푸는 카드면 그냥 새로 시작
- **비교 대상**: 바로 직전 기록이 기본. 최고 기록을 넘으면 "최고 기록 경신!" 표시를 더한다
- **시간 단위**: 한 문제(단계)당, 문제가 화면에 뜬 순간 ~ 제출까지. **전체 완주 시간은 쓰지 않는다** (카드뉴스·해설 읽는 시간이 섞이고, 두 번째엔 읽기를 건너뛰어서)
- **시간 비교에서 빼는 단계**: 개념 단계(매번 문제가 달라 짝을 지을 수 없음), 판단해보기(글 길이에 좌우됨). 시간 기록은 모든 문제에서 하고(FSRS, B안 검증 실험에 씀), 고스트 화면에서 나란히 비교하지 않을 뿐이다
- **보여 주는 곳**: 푸는 도중엔 "지난번엔 맞혔어요" 정도만 작게, 자세한 비교는 결과 화면에서 한 번에. 말투는 사실만 ("지난번 12초 · 이번 15초")
- 결과 화면 (카드 유형에 있는 단계만 나온다):

  ```
  지난번(11/20)보다 2단계 좋아졌어요
  🏆 인과 순서 최고 기록 경신!

              지난번          이번
  개념 단계    5문제 필요  →   2문제 필요
  퀴즈        ✓ 12초     →   ✓ 5초
  차트 읽기    ✓ 25초     →   ✓ 22초
  인과 순서    ✗ 40초     →   ✓ 18초  🏆
  판단해보기   52점       →   71점

  확신: 지난번 "확신해요"인데 틀림 1개 → 이번 0개
  ```

- 단계별 비교 방법:
  - **개념 단계**: 튜터 에이전트가 그때 지식 상태로 문제를 고르니 매번 문제가 다르다. 그래서 시간이 아니라 **통과까지 필요한 문제 수**를 비교한다 (줄었으면 개념을 익혀서 덜 물어본 것 = 개인화가 작동한다는 근거)
  - **퀴즈·차트 읽기·인과 순서**: 같은 문제라 정답 + 시간을 그대로 비교
  - **판단해보기 (서술형)**: 시간은 글 길이에 좌우되므로 빼고 **점수**를 비교
- "좋아졌어요" 판단 순서: ① 틀림 → 맞힘 ② 둘 다 맞혔으면 시간이 줄었을 때 ③ 확신하고 틀린 개수가 줄었을 때. 정답이 시간보다 먼저다
  - ②의 "시간이 줄었다"의 기준은 **고스트 담당이 근거를 찾아 정한다.** 가장 단순하게는 조금이라도 줄면 좋아진 것으로 봐도 된다. 다만 몇 초 차이는 우연일 수 있으니, 응답 시간 변동이나 반복 연습 효과를 다룬 문헌에서 설득력 있는 기준(예: 일정 비율 이상 감소)을 찾으면 그걸 쓰고 문서에 근거를 적는다
- 같은 개념, 다른 문제 (복습) 비교도 따로 둔다: "처음 배울 때 vs 지금" 정답률, 응답 시간, 알 확률. 문제 길이가 달라서 응답 시간은 문제별 평균 대비로 보정한다
- 주의: 같은 카드는 문제를 외워서 빨라졌을 수 있다. 그래서 카드 고스트는 "기록 갱신"으로 보여 주고, "실력이 늘었다"의 주 근거는 같은 개념·다른 문제 쪽으로 한다
- 이 데이터는 실제 사용자 기준 "전후 비교"라서 가상 학습자 평가(1-5)를 보완하는 발표 근거가 된다

## 6. 시작 전 공유할 초안 (개발하면서 조정)

회의로 정할 필요 없이 아래 초안대로 시작하고, 개발하다 바꿀 게 생기면 서로 알린다. 본인 쪽이 먼저 필요하면 가짜 값으로 먼저 개발한다.

| 방향 | 이름 | 모양 (초안) |
| :--- | :--- | :--- |
| 사람2 → 사람1 | `get_mastery(user_id)` | `{concept_id: p_know}` |
| 사람1 → 사람2 | 개념 지도 테이블 | `concept_nodes(id, label, aliases)`, `concept_prereq(pre_id, post_id, votes)` |
| 사람1 → 사람2 | 재도전 기록 | user_answers의 `attempt_no` |

테이블 초안 (사람2가 009 마이그레이션으로 확정):

```
user_answers  + confidence SMALLINT (1 애매, 2 확신, 판단해보기는 NULL), response_ms INT, answer_changes INT, attempt_no INT
user_concept_state (user_id, concept_id, p_know, stability, difficulty, last_review_at, due_at, updated_at)
concept_nodes (id, label, aliases, created_at)
concept_prereq (pre_id, post_id, votes, PRIMARY KEY (pre_id, post_id))
```

기존 `user_concepts(correct, total)`는 바로 지우지 않고, 새 상태가 안정되면 정리한다.
